# Ragged v0.9.0 - Web API Foundation

**Status:** Completed

**Release Date:** 2025-11-28

**Focus:** Backend API infrastructure for Web UI features

---

## Overview

Version 0.9.0 establishes the comprehensive backend API infrastructure required for the v0.9 Web UI features. This release provides RESTful APIs with full Pydantic validation, SSE streaming support, and modular router architecture.

**Dependencies:** Requires v0.8 (agent workflows backend), v0.6 (security middleware)

---

## Implemented Features

### Document Library API

**Endpoints:**
- `GET /api/documents` - List documents with pagination and filtering
- `GET /api/documents/{document_id}` - Get document details
- `GET /api/documents/{document_id}/chunks` - Get document chunks
- `DELETE /api/documents/{document_id}` - Delete document
- `PATCH /api/documents/{document_id}` - Update document metadata
- `GET /api/documents/search` - Search documents by query
- `GET /api/documents/stats` - Get document statistics
- `POST /api/documents/batch-delete` - Batch delete documents

**Features:**
- Pagination with configurable page size
- Metadata filtering
- Search across document content
- Document statistics and analytics

**Files:**
- `src/web/routers/documents.py` (~400 lines)
- `src/web/schemas/documents.py` (~200 lines)
- `tests/web/test_documents_api.py` (~500 lines, 32 tests)

### Knowledge Graph API

**Endpoints:**
- `GET /api/graph/data` - Get graph data (nodes and edges)
- `GET /api/graph/nodes/{node_id}` - Get node details
- `GET /api/graph/nodes/{node_id}/neighbors` - Get node neighbours
- `POST /api/graph/entities` - Add entity to graph
- `POST /api/graph/relationships` - Add relationship
- `DELETE /api/graph/entities/{entity_id}` - Remove entity
- `GET /api/graph/search` - Search graph by query
- `GET /api/graph/stats` - Get graph statistics
- `GET /api/graph/export` - Export graph (JSON/GEXF)
- `POST /api/graph/import` - Import graph data
- `POST /api/graph/build` - Build graph from documents

**Features:**
- Full CRUD operations for entities and relationships
- Neighbour traversal with depth control
- Multiple export formats (JSON, GEXF)
- Graph statistics and metrics
- Lazy initialisation of KnowledgeGraph

**Files:**
- `src/web/routers/graph.py` (~500 lines)
- `src/web/schemas/graph.py` (~300 lines)
- `tests/web/test_graph_api.py` (~700 lines, 43 tests)

### Workflow API

**Endpoints:**
- `GET /api/workflows` - List all workflows
- `GET /api/workflows/templates` - List workflow templates
- `GET /api/workflows/{workflow_id}` - Get workflow definition
- `POST /api/workflows` - Create custom workflow
- `POST /api/workflows/validate` - Validate workflow definition
- `DELETE /api/workflows/{workflow_id}` - Delete workflow
- `POST /api/workflows/{workflow_id}/execute` - Execute workflow
- `GET /api/workflows/{workflow_id}/execute/{execution_id}/stream` - Stream execution progress (SSE)
- `GET /api/workflows/executions` - List all executions
- `GET /api/workflows/executions/{execution_id}` - Get execution details
- `POST /api/workflows/executions/{execution_id}/cancel` - Cancel execution

**Features:**
- Built-in workflow templates (search_and_summarise, document_analysis, multi_source_qa)
- Custom workflow creation with validation
- Async workflow execution with progress streaming
- Server-Sent Events (SSE) for real-time progress
- Execution history and result storage
- Cancellation support

**Files:**
- `src/web/routers/workflows.py` (~730 lines)
- `src/web/schemas/workflows.py` (~230 lines)
- `tests/web/test_workflows_api.py` (~600 lines, 39 tests)

## Architecture

### Router Organisation

```
src/web/
├── api.py              # Main FastAPI app with middleware
├── routers/
│   ├── __init__.py     # Router exports
│   ├── documents.py    # Document Library API
│   ├── graph.py        # Knowledge Graph API
│   └── workflows.py    # Workflow API
└── schemas/
    ├── __init__.py     # Schema exports
    ├── documents.py    # Document Pydantic models
    ├── graph.py        # Graph Pydantic models
    └── workflows.py    # Workflow Pydantic models
```

### Key Design Decisions

1. **Modular Routers:** Each feature domain has its own router for maintainability
2. **Pydantic Schemas:** Full request/response validation with Field constraints
3. **Lazy Initialisation:** Services initialised on first use to reduce startup time
4. **SSE Streaming:** Real-time progress updates for long-running operations
5. **Route Ordering:** Specific routes before path parameters to avoid conflicts
