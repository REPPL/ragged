## Security Considerations

### Cross-Site Scripting (XSS) Prevention

**Input Sanitization:**
- Sanitise all user inputs before rendering (queries, document names, metadata)
- Use Svelte's default escaping (avoid `{@html}` unless absolutely necessary)
- Sanitise file upload names and metadata
- Validate and escape API responses before display

**Content Security Policy (CSP):**
- Strict CSP headers to prevent inline scripts
- Whitelist trusted sources for scripts, styles, images
- No `unsafe-inline` or `unsafe-eval` in production
- Report-only mode during development, enforce in production

### Cross-Site Request Forgery (CSRF) Protection

**Token Management:**
- SvelteKit CSRF protection enabled by default
- Validate CSRF tokens on all state-changing operations
- Use SameSite cookies (Strict or Lax)
- Origin/Referer header validation

**API Authentication:**
- Include API tokens in headers, not query parameters
- Validate origin for all API requests
- Use secure, httpOnly cookies for session management

### Secure API Communication

**HTTPS Enforcement:**
- All API calls over HTTPS in production
- TLS 1.2+ minimum version
- Certificate validation enforced
- No mixed content (HTTP resources on HTTPS pages)

**API Security:**
- Store API keys/tokens securely (not in localStorage, use httpOnly cookies)
- Implement request signing for sensitive operations
- Rate limit API calls from client-side
- Handle API errors gracefully without exposing sensitive information

### File Upload Security

**Upload Validation:**
- Client-side: Validate file type and size before upload
- File type whitelist: PDF, images (PNG, JPG), markdown
- Maximum file size: 50MB per file, 200MB per batch
- Virus scanning integration (future: ClamAV)

**Path Traversal Prevention:**
- Sanitise filenames (remove ../, absolute paths, special characters)
- Generate server-side UUIDs for file storage
- Never use user-provided filenames directly
- Validate file extensions against MIME types

### Authentication & Authorisation

**Session Management:**
- Secure session cookies (httpOnly, Secure, SameSite=Strict)
- Session timeout after 30 minutes of inactivity
- Logout functionality clears all session data
- CSRF protection for login/logout

**Future OAuth Integration:**
- Prepare architecture for OAuth 2.0 / OpenID Connect
- Token refresh mechanism
- Secure token storage

### Security Testing

- [ ] XSS tests (inject scripts in query inputs, filenames, document names)

## Configuration

### Security Settings

```typescript
// src/lib/config/security.ts
export const securityConfig = {
  csp: {
    defaultSrc: ["'self'"],
    scriptSrc: ["'self'"],
    styleSrc: ["'self'", "'unsafe-inline'"], // Tailwind requires inline
    imgSrc: ["'self'", "data:", "https:"],
    connectSrc: ["'self'", process.env.VITE_API_URL],
    fontSrc: ["'self'"],
    objectSrc: ["'none'"],
    upgradeInsecureRequests: true
  },

  fileUpload: {
    maxFileSize: 50 * 1024 * 1024, // 50MB
    maxBatchSize: 200 * 1024 * 1024, // 200MB
    allowedTypes: [
      'application/pdf',
      'image/png',
      'image/jpeg',
      'text/markdown'
    ],
    scanForViruses: false // Enable in production with ClamAV
  },

  session: {
    timeout: 30 * 60 * 1000, // 30 minutes
    cookieOptions: {
      httpOnly: true,
      secure: true,
      sameSite: 'strict'
    }
  },

  rateLimiting: {
    queriesPerMinute: 60,
    uploadsPerMinute: 10
  }
}
```

## Migration Guide

### From v0.6.7

**No Breaking Changes Before v1.0** - Breaking changes are acceptable in pre-1.0 versions. No migration compatibility layer required.

**New UI:** Replaces Gradio demo UI from v0.5.4 with modern Svelte/SvelteKit application.

**What Changes:**
- Web UI framework: Gradio → SvelteKit
- Styling: Gradio defaults → Tailwind CSS
- API integration: Direct Ollama calls → FastAPI REST Layer (v0.6.7)

**Migration Steps:**
1. Install Node.js 18+ and npm
2. Run `npm install` in web UI directory
3. Configure environment variables (`.env.local`)
4. Run `npm run dev` for development
5. Run `npm run build` for production bundle

**Data Compatibility:**
- No changes to backend data storage
- Existing documents and queries accessible via new UI
- Query history preserved (backend stores)

## Performance Impact

### Expected Metrics

**Initial Load:**
- Bundle size: ~300-500KB (gzipped)
- Time to First Byte (TTFB): <500ms
- First Contentful Paint (FCP): <1.5s
- Time to Interactive (TTI): <3s

**Runtime Performance:**
- Query input latency: <50ms
- Document upload progress: Real-time updates
- Results rendering: <200ms for 10 results
- Memory usage: ~50-100MB (typical session)

**Network:**
- API calls: Batched and cached where possible
- Image uploads: Chunked for large files
- Query results: Paginated (10-20 per page)
