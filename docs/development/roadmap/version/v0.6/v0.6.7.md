**What This Version Delivers:**

- Document management, query, and monitoring endpoints
- CORS configuration for UI-backend communication

**Why After Optimisation Features:**

- Features stabilised and ready for API exposure

## API Contract Specification

### OpenAPI 3.1 Template Structure

**File**: `src/api/openapi.yaml` (generated from FastAPI decorators)

**Core Structure:**
```yaml
openapi: 3.1.0
info:
  title: ragged API
  version: 1.0.0
  description: Multi-modal RAG system with vision capabilities

servers:
  - url: http://localhost:8000/api/v1
    description: Local development
  - url: https://api.ragged.dev/v1
    description: Production (future)

components:
  schemas:
    Document:
      type: object
      properties:
        document_id: { type: string, format: uuid }
        filename: { type: string }
        pages: { type: integer }
        embeddings_count: { type: integer }
        created_at: { type: string, format: date-time }

    QueryRequest:
      type: object
      required: [query]
      properties:
        query: { type: string }
        context_scope: { type: string, enum: [narrow, medium, broad], default: medium }
        top_k: { type: integer, default: 5, minimum: 1, maximum: 20 }

    QueryResult:
      type: object
      properties:
        chunk_id: { type: string }
        content: { type: string }
        score: { type: number }
        document_id: { type: string }
        page_number: { type: integer }
        metadata: { type: object }

  securitySchemes:
    ApiKeyAuth:
      type: apiKey
      in: header
      name: X-API-Key
```

**Full spec reference**: See v0.6/README.md API Contracts section for complete endpoint contracts.

**SDK Generation**: Use OpenAPI Generator to create client SDKs in v0.6.10.

## Security Considerations

### Authentication & Authorization

**API Key Authentication:**
- Bearer token authentication via `Authorization: Bearer <token>` header
- Alternative: `X-API-Key` header support
- Secure key generation (cryptographically random, 32+ bytes)
- Key rotation support
- Key revocation endpoint

**Authorization:**
- Role-based access control (RBAC): admin, user, readonly
- Per-endpoint permission checks
- Document ownership validation
- Query history access control

**Key Storage:**
- Hashed keys in database (bcrypt/argon2)
- Never log full API keys
- Secure key transmission (HTTPS only)
- Key metadata (created, last used, expiry)

### Input Validation

**Request Validation:**
- Pydantic v2 models for all endpoints
- Maximum request size: 100MB (file uploads)
- Maximum query length: 10,000 characters
- JSON schema validation
- Reject malformed requests

**File Upload Validation:**
- Allowed file types: PDF only (whitelist)
- Magic number validation (not just extension)
- Maximum file size: 50MB per upload
- Virus scanning (optional, ClamAV integration)
- Filename sanitisation (prevent path traversal)

**Injection Prevention:**
- SQL injection: Parameterised queries (SQLAlchemy ORM)
- NoSQL injection: Validate metadata filters
- Command injection: No shell execution from user input
- Path traversal: Validate and sanitise all file paths
- XSS: Sanitise all user-provided strings in responses

### Rate Limiting

**Global Rate Limits:**
- 1000 requests/hour per API key (default)
- 100 requests/hour for unauthenticated (health checks)
- 429 status code when exceeded
- Rate limit headers: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`

**Endpoint-Specific Limits:**
- Document upload: 10/hour per key
- Query endpoints: 100/hour per key
- File download: 50/hour per key
- Analytics endpoints: 20/hour per key

**DDoS Protection:**
- IP-based rate limiting (in addition to key-based)
- Request queue size limits
- Connection timeout enforcement
- Slow request protection

### CORS Configuration

**Allowed Origins:**
- Configurable whitelist of origins
- Development: `http://localhost:*` (ports 3000, 5000, 5173)
- Production: Specific domain(s) only
- No wildcard `*` in production

**CORS Headers:**
- `Access-Control-Allow-Origin`: Whitelist only
- `Access-Control-Allow-Methods`: GET, POST, DELETE (specific verbs)
- `Access-Control-Allow-Headers`: Content-Type, Authorization, X-API-Key
- `Access-Control-Max-Age`: 86400 (24 hours)
- Credentials: `Access-Control-Allow-Credentials: true` (if needed)

### HTTPS & Transport Security

**TLS Configuration:**
- HTTPS enforced in production
- TLS 1.2+ only (no SSLv3, TLS 1.0, TLS 1.1)
- Strong cipher suites only
- HSTS header: `Strict-Transport-Security: max-age=31536000; includeSubDomains`

**Security Headers:**
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `X-XSS-Protection: 1; mode=block`
- `Content-Security-Policy`: Restrictive policy
- `Referrer-Policy: strict-origin-when-cross-origin`

### Error Handling

**Secure Error Responses:**
- No stack traces in production
- Generic error messages (don't leak implementation details)
- Detailed logs server-side only
- Rate limit error responses (prevent information disclosure)

**Error Codes:**
- 400: Bad Request (invalid input)
- 401: Unauthorised (missing/invalid auth)
- 403: Forbidden (insufficient permissions)
- 404: Not Found (resource doesn't exist)
- 429: Too Many Requests (rate limit exceeded)
- 500: Internal Server Error (generic server error)

### Logging & Monitoring

**Access Logging:**
- Log all API requests (method, endpoint, status, latency)
- Log authentication attempts (success/failure)
- Log rate limit violations
- Redact sensitive data (API keys, passwords, PII)

**Security Event Logging:**
- Failed authentication attempts
- Authorization failures
- Suspicious patterns (scanning, brute force)
- File upload rejections
- Rate limit violations

**Log Storage:**
- Secure log storage (access controlled)
- Log rotation and retention (30 days default)
- Audit trail immutability
- Log shipping to SIEM (optional)

## Migration Guide

### From v0.6.6

**No Breaking Changes Before v1.0** - Breaking changes are acceptable in pre-1.0 versions. No migration compatibility layer required.

**New Dependencies:**
- FastAPI
- Uvicorn (ASGI server)
- Pydantic v2
- python-multipart (file uploads)
- Optional: python-jose (JWT tokens)

**Configuration Changes:**
- Add `api` section to config.yml (see above)
- Generate initial API keys
- Configure CORS origins

**API Endpoints:**
- All endpoints prefixed with `/api/v1/`
- Authentication required by default (can disable per endpoint)

### API Usage

**Authentication:**
```bash
# Using X-API-Key header
curl -H "X-API-Key: rg_..." http://localhost:8000/api/v1/documents

# Using Bearer token
curl -H "Authorization: Bearer rg_..." http://localhost:8000/api/v1/documents
```

**Document Upload:**
```bash
curl -X POST http://localhost:8000/api/v1/documents/upload \
  -H "X-API-Key: rg_..." \
  -F "file=@document.pdf"
```

**Query:**
```bash
curl -X POST http://localhost:8000/api/v1/query/text \
  -H "X-API-Key: rg_..." \
  -H "Content-Type: application/json" \
  -d '{"query": "What is RAG?", "top_k": 5}'
```
