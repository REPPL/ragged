## Features

### OPTIMISE-007: CLI Analytics Commands (15-20 hours)

**Purpose:** CLI commands to analyse query performance, routing decisions, cache efficiency, and optimisation feature usage.

#### New CLI Commands

**1. `ragged analytics` (Overview)**
- Display summary performance metrics
- Query latency distribution (p50, p95, p99)
- Query volume over time
- Success/failure rates
- Top queries by frequency

**2. `ragged analytics routing` (Model Routing)**
- Model selection distribution (3b vs 8b vs 70b usage)
- Routing decision accuracy (if feedback provided)
- Average latency per model
- Cost per model (token usage)
- Routing overhead time

**3. `ragged analytics cache` (Cache Performance)**
- Cache hit rate (overall and per query type)
- Cache size and memory usage
- Most cached queries
- Cache effectiveness (latency saved)
- Eviction statistics

**4. `ragged analytics domain` (Domain Adaptation)**
- Domain detection accuracy
- Domain-specific performance metrics
- Domain distribution over time
- Retrieval quality per domain
- Adaptation overhead

**5. `ragged analytics context` (Context Scope)**
- Context scope usage distribution
- Average context window size
- Document/chunk selection patterns
- Context truncation frequency
- Scope recommendation effectiveness

## Security Considerations

### Data Privacy

**Query Privacy:**
- Hash queries before storage (SHA-256)
- No storage of sensitive user data
- Configurable data retention (default: 30 days)
- User opt-out for analytics collection

**Export Security:**
- Validate export paths (prevent directory traversal)
- Export files created with restricted permissions (600)
- No export of raw queries (only hashed)
- Sanitise output in CSV/JSON exports

### Input Validation

**CLI Arguments:**
- Validate time range inputs
- Sanitise query filters
- Validate export file paths
- Rate limit analytics queries

**SQL Injection Prevention:**
- Parameterised queries for all database operations
- No dynamic SQL from user input
- Validate column names for sorting/filtering
- Escape user-provided values

### Resource Management

**Storage Limits:**
- Maximum database size (default: 500MB)
- Automatic cleanup of old data
- Configurable retention policies
- Disk space monitoring

**Query Limits:**
- Maximum time range for analytics queries
- Pagination for large result sets
- Timeout for expensive aggregations
- Rate limiting for analytics commands

## Configuration

### Analytics Settings

```yaml
# config.yml
analytics:
  enabled: true
  collection:
    query_metrics: true
    performance_metrics: true
    routing_metrics: true
    cache_metrics: true
    domain_metrics: true
    context_metrics: true

  privacy:
    hash_queries: true  # SHA-256 hash before storage
    store_query_text: false  # Never store raw queries
    retention_days: 30
    allow_opt_out: true

  storage:
    database_path: "~/.ragged/analytics.db"
    max_database_size_mb: 500
    cleanup_interval_hours: 24

  performance:
    collection_overhead_target_ms: 5
    analytics_query_timeout_ms: 10000
    max_results_per_page: 1000

  export:
    formats: ["json", "csv"]
    default_export_dir: "~/.ragged/exports/"
    file_permissions: "600"  # Owner read/write only
```

## Usage Examples

### Basic Analytics

```bash
# View overall performance metrics
ragged analytics

# View last 7 days
ragged analytics --days 7

# View specific date range
ragged analytics --from 2025-01-01 --to 2025-01-31
```

### Routing Analytics

```bash
# View model routing statistics
ragged analytics routing

# View routing for specific time period
ragged analytics routing --days 30

# Export routing data
ragged analytics routing --export routing_stats.json
```

### Cache Analytics

```bash
# View cache performance
ragged analytics cache

# View cache hit rate trend
ragged analytics cache --trend

# Export cache metrics
ragged analytics cache --export cache_metrics.csv
```

### Domain Analytics

```bash
# View domain detection statistics
ragged analytics domain

# View domain-specific performance
ragged analytics domain --domain code

# Compare domains
ragged analytics domain --compare
```

### Context Analytics

```bash
# View context scope usage
ragged analytics context

# View context window distribution
ragged analytics context --distribution

# Identify truncation patterns
ragged analytics context --truncation
```
