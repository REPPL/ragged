# Ragged v0.8.1 Roadmap - Interactive Installation Wizard & Automation

**Status:** Planned

**Total Hours:** 35-45 hours (AI implementation)

**Focus:** User-friendly installation wizard and one-command automation

**Breaking Changes:** None

**Dependencies:** Requires v0.8.0 completion (prerequisite detection and installation infrastructure)

**Purpose:** Transform installation from "run Python scripts" to "interactive guided experience" with one-command automation for power users

---

## Overview

Version 0.8.1 builds on v0.8.0's foundation to deliver an intuitive installation experience through an interactive CLI wizard and fully automated one-command installation script. Users can choose between guided setup (wizard) or unattended installation (one-command script).

### Problem Statement

**Current Installation (Post-v0.8.0):**
```bash
# Foundation exists but still requires:
python -m ragged.install.detect     # Run detection
python -m ragged.install.install    # Install dependencies
python -m ragged.install.configure  # Configure
python -m ragged.install.verify     # Verify

# Issues:
- Multiple commands required
- No guidance on choices (which model? auth on/off?)
- No progress indication during installation
- Manual steps if automation fails
- Unclear what happens at each step
```

### Target Outcomes

**After v0.8.1 Implementation:**
```bash
# Option 1: Interactive wizard
ragged install

# Option 2: One-command automation
curl -sSL https://install.ragged.ai | sh

# Results:
- ✅ Guided installation with clear prompts
- ✅ Real-time progress indication
- ✅ Smart defaults with override options
- ✅ Automated recovery from failures
- ✅ Post-install verification and setup
- ✅ Ready-to-use ragged in <10 minutes
```

## WIZARD-002: One-Command Installer Script (8-10 hours)

**Problem:** Power users want unattended installation; no automation script exists.

**Implementation:**

1. **Design installer script architecture** [2-2.5 hours]
   - Shell script (bash) for maximum portability
   - Detect OS and architecture automatically
   - Download ragged installer binary/Python package
   - Run installation with default settings
   - Handle errors and provide logs
   - Support flags for customisation:
     - `--no-docker` - Skip Docker installation
     - `--no-webui` - CLI only
     - `--model <name>` - Specify Ollama model
     - `--path <dir>` - Custom install directory
     - `--unattended` - No prompts, use all defaults

2. **Implement core installer logic** [3-4 hours]
   - **Platform detection:**
     ```bash
     OS=$(uname -s | tr '[:upper:]' '[:lower:]')
     ARCH=$(uname -m)
     # OS: darwin, linux, windows
     # ARCH: x86_64, arm64, aarch64
     ```

   - **Download ragged:**
     - PyPI: `pip install ragged`
     - Or: Download standalone binary from GitHub releases
     - Verify checksum for security

   - **Run installation:**
     ```bash
     # Unattended mode (no prompts)
     ragged install --unattended \
       --model llama3.2:3b \
       --no-auth \
       --webui

     # Or interactive (if --unattended not passed)
     ragged install
     ```

   - **Error handling:**
     - Capture exit codes from installation
     - Log to ~/.ragged/install.log
     - Display errors with fix suggestions
     - Provide manual installation link

3. **Add installation flags and customisation** [1.5-2 hours]
   - Parse command-line flags
   - Pass flags to ragged install command
   - Validate flag combinations
   - Provide flag documentation (--help)

4. **Implement download and verification** [1-1.5 hours]
   - Download installer from official URL
   - Verify checksum (SHA256):
     ```bash
     curl -fsSL https://install.ragged.ai/ragged-installer.tar.gz -o /tmp/ragged-installer.tar.gz
     echo "<SHA256> /tmp/ragged-installer.tar.gz" | sha256sum -c -
     ```
   - Extract and run
   - Clean up temporary files

5. **Add hosting and CI/CD** [0.5-1 hour]
   - Host installer script at https://install.ragged.ai
   - CI/CD pipeline to test installer on all platforms
   - Automated checksum generation on release
   - Version selection: `curl -sSL https://install.ragged.ai/v0.8.1 | sh`

**Files:**
- `scripts/install.sh` (new - one-command installer, ~400 lines)
- `scripts/install.ps1` (new - Windows PowerShell installer, ~350 lines)
- `.github/workflows/test-installer.yml` (new - CI/CD installer tests, ~150 lines)
- `docs/installation/one-command.md` (new - installer documentation, ~200 lines)

**Success Criteria:**
- One-command install works on fresh systems (macOS, Linux, Windows)
- Unattended mode completes without prompts
- Flags allow customisation
- Checksum verification prevents tampered installers
- Installation time <10 minutes (average)
- CI/CD tests installer on every commit

## WIZARD-003: Progress Tracking & Status Updates (5-7 hours)

**Problem:** Users don't know what's happening during installation; long silences cause concern.

**Implementation:**

1. **Design progress system** [1.5-2 hours]
   - Progress indicators for all long-running operations:
     - Dependency downloads
     - Docker image pulls
     - Ollama model downloads
     - Database initialisation
     - Service startup
   - Status types:
     - Progress bar (determinate): Download 45.2MB / 120MB [=====>...] 37%
     - Spinner (indeterminate): Installing Docker...
     - Time estimate: ~3 minutes remaining
   - Use `rich` library for beautiful progress bars

2. **Implement download progress tracking** [1.5-2 hours]
   - Hook into download functions (v0.8.0 installers)
   - Track bytes downloaded vs total
   - Calculate download speed (MB/s)
   - Estimate time remaining
   - Display progress bar:
     ```
     Downloading Docker Desktop... ━━━━━╸━━━━━━━━━ 45% 23.5/52.0 MB 12.3 MB/s ETA 00:02
     ```
   - Update in real-time (refresh every 100ms)

3. **Implement installation step tracking** [1.5-2 hours]
   - Track overall installation progress:
     ```
     Installation Progress: [3/7] Installing Ollama

     [✓] Check prerequisites
     [✓] Install Docker
     [●] Install Ollama
     [ ] Install Python dependencies
     [ ] Configure ragged
     [ ] Start services
     [ ] Verify installation
     ```
   - Show current step clearly
   - Provide time estimates per step
   - Display elapsed time

4. **Add logging and verbosity control** [0.5-1 hour]
   - Normal mode: Clean progress bars, minimal output
   - Verbose mode (`--verbose`): Show all commands, stdout/stderr
   - Debug mode (`--debug`): Extremely detailed logging
   - Log file: Always created at ~/.ragged/install.log

**Files:**
- `src/install/progress/tracker.py` (new - progress tracking, ~250 lines)
- `src/install/progress/display.py` (new - UI rendering, ~200 lines)
- `src/install/installers/base.py` (modify - add progress callbacks, ~50 lines)
- `tests/install/progress/` (new - progress tests, ~150 lines)

**Success Criteria:**
- Progress bars update smoothly (no stuttering)
- Time estimates accurate (within 30%)
- Progress visible for all long-running operations
- Verbose mode provides debugging information
- Log file created for troubleshooting

## WIZARD-004: Configuration File Generation (6-8 hours)

**Problem:** Users need guidance on configuration choices; defaults may not suit everyone.

**Implementation:**

1. **Design interactive configuration prompts** [2-2.5 hours]
   - Prompt categories:
     - **Installation Mode:**
       - Full (WebUI + CLI)
       - CLI only
       - Development mode (hot reload, debug logging)
     - **Model Selection:**
       - List available models: llama3.2 (3B, 8B), mistral, etc.
       - Show model sizes and requirements
       - Recommend based on system RAM
     - **Authentication:**
       - Enable authentication? (Yes/No)
       - Generate admin credentials
     - **Ports:**
       - Use defaults (8000, 5173, 8001, 11434)?
       - Or custom ports (detect conflicts)
     - **Storage:**
       - Use default (~/.ragged/)?
       - Or custom path
   - For each prompt:
     - Clear question
     - Explanation of choice
     - Recommended default highlighted
     - Validation of user input

2. **Implement smart defaults** [1.5-2 hours]
   - Detect system capabilities (RAM, CPU, disk space)
   - Recommend model based on RAM:
     - <8GB: llama3.2:3b
     - 8-16GB: llama3.2:8b
     - 16GB+: mistral or llama3:70b (if user wants)
   - Detect existing installations (avoid port conflicts)
   - Use secure defaults (authentication on for production mode)
   - Skip prompts if running unattended (use all defaults)

3. **Implement configuration validation** [1-1.5 hours]
   - Validate user inputs:
     - Ports: numeric, available, not privileged (<1024 without sudo)
     - Paths: writable, sufficient space
     - Model: exists in Ollama library
   - Warn about insecure choices (auth disabled, weak JWT secret)
   - Provide fix suggestions for invalid inputs

4. **Generate configuration files** [1-1.5 hours]
   - Use configuration templates (v0.8.0)
   - Populate with user choices
   - Generate ~/.ragged/config.yaml
   - Generate .env file for secrets
   - Generate docker-compose.yml (if Docker mode)
   - Display generated config summary
   - Allow user to review and edit before proceeding

**Files:**
- `src/cli/wizard/screens/configuration.py` (modify - interactive prompts, ~300 lines)
- `src/config/interactive.py` (new - interactive config generation, ~250 lines)
- `src/config/validation.py` (new - config validation, ~200 lines)
- `src/config/defaults.py` (new - smart defaults, ~150 lines)
- `tests/config/test_interactive.py` (new - interactive config tests, ~200 lines)

**Success Criteria:**
- Prompts clear and well-explained
- Smart defaults work for 80%+ users
- Validation catches invalid inputs
- Generated configs work without manual edits
- Review step allows final checks

## WIZARD-005: Post-Install Verification & Setup (6-8 hours)

**Problem:** Installation may succeed but services fail to start; no end-to-end verification.

**Implementation:**

1. **Implement comprehensive health checks** [2-2.5 hours]
   - Check all services running:
     - Docker daemon
     - Ollama service (port 11434)
     - ChromaDB (port 8001)
     - FastAPI backend (port 8000)
     - SvelteKit frontend (port 5173, if WebUI)
   - Test service connectivity:
     - HTTP requests to health endpoints
     - Verify responses correct (not just 200 OK)
   - Check data persistence:
     - Create test document
     - Query test document
     - Verify retrieval works
   - Measure response times
   - Generate health report:
     ```
     ✅ Ollama: Running (http://localhost:11434) - 12ms
     ✅ ChromaDB: Running (http://localhost:8001) - 8ms
     ✅ FastAPI: Running (http://localhost:8000) - 15ms
     ✅ SvelteKit: Running (http://localhost:5173) - 6ms
     ✅ End-to-end query: Success - 234ms
     ```

2. **Implement service startup automation** [2-2.5 hours]
   - Start all services in correct order:
     1. Docker daemon (if not running)
     2. ChromaDB container
     3. Ollama service
     4. FastAPI backend
     5. SvelteKit frontend (if WebUI)
   - Wait for health checks before proceeding
   - Timeout after 2 minutes per service
   - Retry failed services (up to 3 attempts)
   - Display startup progress:
     ```
     Starting services...
     [✓] Docker daemon
     [✓] ChromaDB (port 8001)
     [●] Ollama service (waiting for port 11434)...
     [ ] FastAPI backend
     [ ] SvelteKit frontend
     ```

3. **Implement end-to-end test** [1-1.5 hours]
   - Create test document:
     ```python
     test_doc = {
         "content": "Ragged is a privacy-first RAG system.",
         "metadata": {"source": "test", "type": "verification"}
     }
     ```
   - Ingest test document
   - Query: "What is ragged?"
   - Verify response contains expected content
   - Clean up test data
   - Report success/failure

4. **Add initial setup guidance** [0.5-1 hour]
   - Display next steps after successful installation:
     ```
     ✅ Installation Complete!

     Your ragged instance is ready.

     🌐 Access WebUI: http://localhost:5173
     🔧 API Endpoint: http://localhost:8000
     📚 Documentation: https://ragged.ai/docs

     Next Steps:
     1. Upload your first document:
        ragged ingest document.pdf

     2. Try a query:
        ragged query "What is in my documents?"

     3. Explore the WebUI (http://localhost:5173)

     📖 Need help? Visit https://ragged.ai/docs/getting-started
     ```
   - Create desktop shortcut (if platform supports)
   - Add ragged to PATH
   - Display keyboard shortcuts reference

**Files:**
- `src/install/verification/health_checks.py` (new - service health checks, ~300 lines)
- `src/install/verification/service_startup.py` (new - service startup, ~250 lines)
- `src/install/verification/end_to_end.py` (new - E2E test, ~200 lines)
- `src/install/verification/next_steps.py` (new - post-install guidance, ~150 lines)
- `tests/install/verification/` (new - verification tests, ~350 lines)

**Success Criteria:**
- All health checks pass after installation
- Services start in correct order
- End-to-end test succeeds
- Startup failures detected and diagnosed
- Next steps clear and actionable

## Known Risks

- **Wizard complexity:** Too many prompts may overwhelm users (mitigate: smart defaults, skip options)
- **Download failures:** Network issues may interrupt installation (mitigate: retry logic, resume capability)
- **Platform variations:** Shell script may not work on all platforms (mitigate: extensive testing, PowerShell for Windows)
- **User consent:** Automated installations may surprise users (mitigate: clearly communicate what will be installed)
