# Ragged v0.8.6 Roadmap - Installation Testing & Quality Assurance

**Status:** Planned

**Total Hours:** 15-20 hours (AI implementation)

**Focus:** Comprehensive installation testing across platforms, scenarios, and error conditions

**Breaking Changes:** None

**Dependencies:** Requires v0.8.0-v0.8.5 completion (entire installation system)

**Purpose:** Ensure installation works reliably across all supported platforms, scenarios, and edge cases before production deployment

---

## Overview

Version 0.8.6 implements comprehensive testing and quality assurance for the installation system, covering cross-platform compatibility, installation scenarios (clean install, upgrade, recovery), error handling validation, performance benchmarking, and regression testing. This version ensures installation reliability and prevents regressions.

### Problem Statement

**Current Installation Testing Gaps:**
- No automated cross-platform tests (Windows, macOS, Linux variants)
- Installation scenarios untested (clean install, upgrade, recovery)
- Error recovery logic untested (what if network fails?)
- Performance not benchmarked (is installation too slow?)
- No regression testing (known issues may reappear)
- Edge cases unexplored (low disk space, port conflicts, etc.)
- User acceptance testing missing (real users haven't validated)

### Target Outcomes

**After v0.8.6 Implementation:**
- ✅ Automated tests on 10+ platform/OS combinations
- ✅ All installation scenarios tested (clean, upgrade, recovery)
- ✅ Error recovery validated (network failures, permission issues)
- ✅ Performance benchmarks established (<10 minutes average)
- ✅ Regression test suite prevents known issues
- ✅ Edge cases handled gracefully
- ✅ User acceptance testing confirms usability

## INSTALL-TEST-001: Cross-Platform Automated Tests (4-5 hours)

**Problem:** Installation untested on most platforms; platform-specific bugs undiscovered.

**Implementation:**

1. **Design cross-platform test matrix** [1-1.5 hours]
   - **Windows:**
     - Windows 10 (x64)
     - Windows 11 (x64)
     - Windows Server 2022 (for enterprise testing)
   - **macOS:**
     - macOS 12 Monterey (Intel)
     - macOS 13 Ventura (Intel, Apple Silicon)
     - macOS 14 Sonoma (Apple Silicon)
   - **Linux:**
     - Ubuntu 20.04, 22.04, 24.04
     - Debian 11, 12
     - Fedora 38, 39, 40
     - RHEL 8, 9 (enterprise)
     - Arch Linux (rolling release)
   - Test environments: VMs, Docker containers, GitHub Actions runners

2. **Implement automated installation tests** [1.5-2 hours]
   - Test script runs on all platforms:
     ```python
     def test_installation(platform: str):
         # 1. Provision fresh VM/container
         vm = provision_vm(platform)

         # 2. Run installation
         result = vm.run("curl -sSL https://install.ragged.ai | sh")
         assert result.exit_code == 0

         # 3. Verify services running
         assert vm.run("ragged health").exit_code == 0

         # 4. Run end-to-end test
         assert vm.run("ragged query 'test'").exit_code == 0

         # 5. Cleanup
         vm.destroy()
     ```
   - Run tests in CI/CD (GitHub Actions matrix)

3. **Set up CI/CD test pipeline** [1-1.5 hours]
   - GitHub Actions workflow:
     ```yaml
     name: Installation Tests
     on: [push, pull_request]
     jobs:
       test:
         strategy:
           matrix:
             os: [ubuntu-22.04, macos-13, windows-2022]
             include:
               - os: ubuntu-20.04
               - os: ubuntu-24.04
               - os: macos-14  # Apple Silicon (M1/M2)
         runs-on: ${{ matrix.os }}
         steps:
           - uses: actions/checkout@v4
           - name: Run installation
             run: |
               curl -sSL https://install.ragged.ai | sh
           - name: Verify installation
             run: |
               ragged health
               ragged query "test"
     ```
   - Run on every commit
   - Report failures to developers

4. **Add platform-specific tests** [0.5-1 hour]
   - Windows-specific: Test .exe installer, PATH updates, Start Menu entries
   - macOS-specific: Test .pkg installer, Gatekeeper, notarization
   - Linux-specific: Test .deb/.rpm packages, systemd services

**Files:**
- `tests/install/cross_platform/` (new - platform tests, ~400 lines)
- `.github/workflows/install-test.yml` (new - CI/CD pipeline, ~200 lines)
- `scripts/provision_test_vm.sh` (new - VM provisioning, ~150 lines)

**Success Criteria:**
- Tests pass on all supported platforms
- CI/CD runs on every commit
- Platform-specific features tested
- Test failures caught before release

## INSTALL-TEST-002: Installation Scenario Testing (3-4 hours)

**Problem:** Only clean installs tested; upgrade and recovery scenarios untested.

**Implementation:**

1. **Design installation scenarios** [1-1.5 hours]
   - **Clean install:** Fresh system, no ragged
   - **Upgrade:** v0.8.0 → v0.8.6 (with data migration)
   - **Reinstall:** Uninstall → reinstall (data preserved)
   - **Recovery:** Interrupted install → resume
   - **Downgrade:** v0.8.6 → v0.8.5 (rollback)
   - **Repair:** Corrupted install → repair
   - **Parallel install:** Install v0.8.5 alongside v0.8.6 (testing)

2. **Implement scenario tests** [1-1.5 hours]
   - **Clean install test:**
     ```python
     def test_clean_install():
         # Fresh VM
         vm = provision_vm("ubuntu-22.04")

         # Install
         vm.run("curl -sSL https://install.ragged.ai | sh")

         # Verify
         assert vm.run("ragged --version").stdout == "0.8.6"
         assert vm.run("ragged health").exit_code == 0
     ```

   - **Upgrade test:**
     ```python
     def test_upgrade():
         vm = provision_vm("ubuntu-22.04")

         # Install old version
         vm.run("curl -sSL https://install.ragged.ai/v0.8.0 | sh")
         vm.run("ragged ingest test.pdf")  # Add data

         # Upgrade
         vm.run("ragged upgrade v0.8.6")

         # Verify data preserved
         assert vm.run("ragged query 'test'").exit_code == 0
         assert vm.run("ragged --version").stdout == "0.8.6"
     ```

   - **Recovery test:**
     ```python
     def test_recovery():
         vm = provision_vm("ubuntu-22.04")

         # Start install
         process = vm.run_async("curl -sSL https://install.ragged.ai | sh")

         # Interrupt midway (after 30 seconds)
         time.sleep(30)
         process.kill()

         # Resume
         vm.run("ragged install --resume")

         # Verify completed
         assert vm.run("ragged health").exit_code == 0
     ```

3. **Test data preservation** [0.5-1 hour]
   - Verify documents, embeddings, config preserved across:
     - Upgrades
     - Reinstalls
     - Repairs
   - Test migration paths (v0.8.0 → v0.8.6)

**Files:**
- `tests/install/scenarios/` (new - scenario tests, ~400 lines)
- `tests/install/scenarios/upgrade.py` (new - upgrade tests, ~200 lines)
- `tests/install/scenarios/recovery.py` (new - recovery tests, ~150 lines)

**Success Criteria:**
- All scenarios tested and pass
- Data preserved across upgrades
- Recovery works after interruption
- Downgrade/rollback functional

## INSTALL-TEST-003: Error Recovery Validation (3-4 hours)

**Problem:** Error recovery logic untested; unknown if automated fixes work.

**Implementation:**

1. **Design error injection framework** [1-1.5 hours]
   - Inject errors during installation:
     - **Network failures:** Simulate download timeouts
     - **Permission errors:** Remove write permissions
     - **Disk full:** Fill disk during installation
     - **Port conflicts:** Start service on conflicting port
     - **Dependency failures:** Corrupt downloaded files
     - **Service crashes:** Kill services during startup
   - Test automated recovery (v0.8.2 REFINE-002)

2. **Implement error injection tests** [1-1.5 hours]
   - **Network failure test:**
     ```python
     def test_network_failure_recovery():
         vm = provision_vm("ubuntu-22.04")

         # Block network during download
         vm.run("iptables -A OUTPUT -p tcp --dport 443 -j DROP")

         # Attempt install (should fail, then retry)
         result = vm.run("curl -sSL https://install.ragged.ai | sh")

         # Verify retry logic activated
         assert "Retrying download" in result.stdout

         # Unblock network
         vm.run("iptables -D OUTPUT -p tcp --dport 443 -j DROP")

         # Installation should complete
         assert result.exit_code == 0
     ```

   - **Disk full test:**
     ```python
     def test_disk_full_recovery():
         vm = provision_vm("ubuntu-22.04")

         # Fill disk (leave only 500MB)
         vm.run("dd if=/dev/zero of=/tmp/fill bs=1M count=<size>")

         # Attempt install (should detect and abort)
         result = vm.run("curl -sSL https://install.ragged.ai | sh")

         assert "Insufficient disk space" in result.stderr
         assert result.exit_code != 0

         # Free space
         vm.run("rm /tmp/fill")

         # Retry install
         result = vm.run("ragged install --resume")
         assert result.exit_code == 0
     ```

3. **Validate recovery strategies** [0.5-1 hour]
   - Test each recovery strategy (v0.8.2):
     - Service restart
     - Permission fixes
     - Cache clearing
     - Configuration repair
   - Verify success rates (>80% target)

**Files:**
- `tests/install/error_injection/` (new - error injection tests, ~400 lines)
- `tests/install/error_injection/network.py` (new - network failure tests, ~150 lines)
- `tests/install/error_injection/resources.py` (new - resource failure tests, ~150 lines)

**Success Criteria:**
- All error scenarios tested
- Automated recovery succeeds >80%
- Manual recovery documented for remaining 20%
- No crashes or data loss during errors

## INSTALL-TEST-004: Performance Benchmarking (2-3 hours)

**Problem:** Installation performance unknown; may be too slow for users.

**Implementation:**

1. **Design performance benchmarks** [0.5-1 hour]
   - Metrics to measure:
     - Total installation time (target: <10 minutes)
     - Dependency download time
     - Service startup time
     - Post-install verification time
   - Test conditions:
     - Fast network (100 Mbps)
     - Slow network (3G simulation)
     - Low-end hardware (2 CPU cores, 4GB RAM)
     - High-end hardware (8+ CPU cores, 16GB+ RAM)

2. **Implement performance tests** [1-1.5 hours]
   - Benchmark script:
     ```python
     def benchmark_installation():
         vm = provision_vm("ubuntu-22.04")

         start = time.time()
         vm.run("curl -sSL https://install.ragged.ai | sh")
         total_time = time.time() - start

         assert total_time < 600  # < 10 minutes

         # Breakdown
         download_time = extract_metric("Download time", vm.logs)
         startup_time = extract_metric("Service startup time", vm.logs)

         return {
             "total": total_time,
             "download": download_time,
             "startup": startup_time,
         }
     ```
   - Run on different hardware configurations
   - Compare across versions (detect regressions)

3. **Create performance reports** [0.5-1 hour]
   - Generate performance report:
     ```
     Installation Performance Benchmark

     Platform: Ubuntu 22.04 (4 CPU, 8GB RAM)
     Network: 100 Mbps

     Metrics:
     - Total time: 8m 23s ✅ (<10m target)
     - Download time: 5m 12s
     - Startup time: 2m 45s
     - Verification time: 26s

     Historical comparison:
     v0.8.5: 9m 10s (-8% faster)
     v0.8.0: 12m 34s (-33% faster)
     ```
   - Track over time (detect performance regressions)

**Files:**
- `tests/install/performance/` (new - performance tests, ~250 lines)
- `tests/install/performance/benchmark.py` (new - benchmarking, ~200 lines)

**Success Criteria:**
- Installation completes in <10 minutes (average)

- Slow network scenarios tested

         """Regression test for issue #123: Port conflicts not detected."""
         vm = provision_vm("ubuntu-22.04")

         # Start service on port 8000
         vm.run("python3 -m http.server 8000 &")

## Known Risks

- **Test environment costs:** Running tests on many platforms expensive (mitigate: use GitHub Actions free tier, optimize test duration)
- **Flaky tests:** Installation tests may be unreliable (mitigate: retry logic, longer timeouts)
- **Test maintenance:** Tests require updates when code changes (mitigate: modular test design, clear documentation)
