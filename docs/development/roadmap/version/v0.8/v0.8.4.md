# Ragged v0.8.4 Roadmap - Embedded ChromaDB Option (Conditional)

**Status:** Conditional (implement only if Docker-free deployment demand exists)

**Total Hours:** 18-28 hours (AI implementation)

**Focus:** Docker-free deployment with embedded ChromaDB

**Breaking Changes:** None (embedded mode is opt-in alternative)

**Dependencies:** Requires v0.8.0-v0.8.2 completion (installation foundation)

**Purpose:** Enable ragged deployment without Docker for resource-constrained environments, corporate firewalls, or users preferring simpler setups

---

## Overview

Version 0.8.4 introduces embedded ChromaDB mode, allowing ragged to run entirely without Docker. ChromaDB runs as an in-process Python library instead of a Docker container, simplifying deployment while maintaining full functionality.

**Rationale for Conditional Status:** Docker is widely available and provides isolation, consistency, and easier updates. Embedded mode adds complexity (Python dependency management, OS-specific issues) and may perform worse. Implementation depends on validated demand for Docker-free deployment.

### Decision Criteria

**Implement v0.8.4 if:**
- ✓ Docker-free deployment requested (>15 independent requests)
- ✓ Resource-constrained environments (Raspberry Pi, low-memory VPS)
- ✓ Corporate firewalls block Docker Hub
- ✓ Users prefer simplicity (fewer moving parts)
- ✓ Python-native deployment desired (easier distribution via PyPI)

**Skip v0.8.4 if:**
- ✗ Docker adoption universal (<5 Docker-free requests)
- ✗ Embedded mode complexity outweighs benefits
- ✗ Performance/scalability trade-offs unacceptable
- ✗ Docker Desktop licensing not a concern

**Decision Point:** After v0.8.2 release and user feedback on deployment preferences

---

## Problem Statement

**Current Deployment (Docker mode):**
```bash
# Docker required
docker-compose up -d chromadb
```

**Issues with Docker:**
- Docker Desktop: 2GB+ download, resource-intensive
- Corporate environments: Firewalls block Docker Hub
- Raspberry Pi: Docker performance poor on ARM
- Simplicity: Users want fewer dependencies
- Licensing: Docker Desktop requires paid license for large enterprises

### Target Outcomes

**After v0.8.4 Implementation:**
```bash
# Embedded mode (no Docker)
ragged install --mode embedded
```

**Results:**
- ✅ ChromaDB runs in-process (Python library)
- ✅ No Docker required
- ✅ Reduced resource usage (<500MB RAM)
- ✅ Simpler deployment (one Python process)
- ✅ Migration between Docker ↔ embedded modes
- ✅ Feature parity with Docker mode

## EMBED-001: Embedded ChromaDB Integration (6-8 hours)

**Problem:** ChromaDB currently runs in Docker; no in-process mode implemented.

**Implementation:**

1. **Research ChromaDB embedded mode** [1-1.5 hours]
   - ChromaDB Python client supports both:
     - **Client mode:** Connect to Docker container (current)
     - **Embedded mode:** In-process database (new)
   - Embedded mode uses SQLite backend (persistent storage)
   - API identical (no code changes to ragged query logic)
   - Limitations:
     - Single process (no multi-process access)
     - SQLite file locking (Windows issues)
     - Less isolated (crashes affect ragged)

2. **Implement embedded ChromaDB client** [2-2.5 hours]
   - Modify ChromaDB initialisation:
     ```python
     # Docker mode (current)
     import chromadb
     client = chromadb.HttpClient(host="localhost", port=8001)

     # Embedded mode (new)
     import chromadb
     client = chromadb.PersistentClient(path="~/.ragged/chromadb")
     ```
   - Configuration to select mode:
     ```yaml
     chromadb:
       mode: embedded  # or 'docker'
       path: ~/.ragged/chromadb  # for embedded mode
       host: localhost  # for docker mode
       port: 8001       # for docker mode
     ```
   - Auto-detect mode based on configuration
   - Fallback: Docker → embedded if Docker unavailable

3. **Handle database initialisation** [1.5-2 hours]
   - Create persistent storage directory: `~/.ragged/chromadb/`
   - Set file permissions (user-only read/write)
   - Initialise ChromaDB database on first run
   - Create default collection
   - Handle migration from Docker to embedded (see EMBED-004)

4. **Add health checks for embedded mode** [0.5-1 hour]
   - Check database file exists and is readable
   - Verify collection accessible
   - Test query functionality
   - Monitor database file size

5. **Implement cleanup and maintenance** [0.5-1 hour]
   - Vacuum SQLite database: `VACUUM;` (reclaim space)
   - Check database integrity: `PRAGMA integrity_check;`
   - Backup database file
   - Rotation of old backups

**Files:**
- `src/database/chromadb_client.py` (modify - add embedded mode, ~200 lines)
- `src/database/embedded.py` (new - embedded ChromaDB logic, ~250 lines)
- `src/config/chromadb.py` (modify - mode selection, ~100 lines)
- `tests/database/test_embedded.py` (new - embedded mode tests, ~300 lines)

**Success Criteria:**
- Embedded mode works without Docker
- API identical to Docker mode (no code changes)
- Database persists across restarts
- Health checks detect issues
- Cleanup reduces disk usage

## EMBED-002: Standalone Deployment Mode (4-6 hours)

**Problem:** Embedded ChromaDB alone insufficient; need full standalone deployment (no Docker anywhere).

**Implementation:**

1. **Design standalone architecture** [1-1.5 hours]
   - **Components:**
     - Ragged CLI (Python)
     - ChromaDB (embedded, in-process)
     - Ollama (standalone, not Docker)
     - FastAPI backend (optional, for WebUI)
     - SvelteKit frontend (optional, development server)
   - **Removed:**
     - Docker daemon
     - Docker Compose
     - All containers
   - **Benefits:**
     - Single Python process (CLI only)
     - Or three processes (CLI + FastAPI + SvelteKit)
     - No container orchestration
     - Easier debugging

2. **Implement standalone installation** [1.5-2 hours]
   - Modify v0.8.0 installation to support standalone mode
   - Skip Docker detection and installation
   - Install ChromaDB Python library: `pip install chromadb`
   - Install Ollama directly (not via Docker)
   - Configure embedded mode automatically
   - Update prerequisites check (no Docker required)

3. **Implement process management** [1-1.5 hours]
   - Since no Docker Compose, manage processes manually:
     - **Ollama:** System service or background process
     - **FastAPI:** `uvicorn` process (if WebUI enabled)
     - **SvelteKit:** `npm run dev` process (if WebUI in dev mode)
   - Create process manager:
     - Start all services in order
     - Monitor health
     - Restart failed services
     - Stop all services on shutdown
   - Or systemd services (Linux), launchd (macOS), Windows services

4. **Add standalone mode documentation** [0.5-1 hour]
   - Explain trade-offs (vs Docker mode)
   - Installation guide for standalone mode
   - Troubleshooting common issues
   - Performance expectations

**Files:**
- `src/install/standalone/installer.py` (new - standalone installation, ~300 lines)
- `src/install/standalone/process_manager.py` (new - process management, ~250 lines)
- `docs/installation/standalone-mode.md` (new - documentation, ~300 lines)
- `tests/install/standalone/` (new - standalone tests, ~250 lines)

**Success Criteria:**
- Standalone mode installs without Docker
- All services start correctly
- Process manager restarts failed services
- WebUI works in standalone mode
- Documentation clear

## EMBED-003: Resource Usage Optimisation (3-4 hours)

**Problem:** Embedded mode may use excessive resources; need optimisation for low-memory environments.

**Implementation:**

1. **Benchmark resource usage** [1-1.5 hours]
   - Measure Docker mode vs embedded mode:
     - **Memory:** Baseline, with 1000 documents, during query
     - **Disk:** Database size, cache size, log size
     - **CPU:** Idle, during ingestion, during query
   - Identify bottlenecks
   - Target: <500MB RAM, <2GB disk

2. **Optimise memory usage** [1-1.5 hours]
   - **Reduce embedding cache size:**
     - Limit in-memory cache: 100MB max
     - Use LRU eviction policy
     - Persist cache to disk (mmap if possible)
   - **Optimise ChromaDB settings:**
     - Adjust batch sizes (smaller batches = less memory)
     - Limit concurrent queries
     - Use lazy loading for results
   - **Reduce model memory:**
     - Suggest smaller Ollama models (llama3.2:3b instead of :70b)
     - Unload models when not in use (if Ollama supports)

3. **Optimise disk usage** [0.5-1 hour]
   - **Database compression:**
     - Enable SQLite compression (if available)
     - Vacuum regularly (reclaim deleted space)
   - **Log rotation:**
     - Limit log file sizes (10MB max per file)
     - Keep only last 7 days
     - Compress old logs
   - **Cache management:**
     - Clear stale cache entries (>30 days old)
     - Limit total cache size (1GB max)

**Files:**
- `src/database/optimisation.py` (new - resource optimisation, ~200 lines)
- `src/config/resource_limits.py` (new - resource limits config, ~100 lines)
- `tests/database/test_optimisation.py` (new - optimisation tests, ~150 lines)

**Success Criteria:**
- Memory usage <500MB (typical workload)
- Disk usage <2GB (1000 documents)
- Performance acceptable (<20% slower than Docker mode)
- Resource limits configurable

## EMBED-004: Migration Between Modes (3-4 hours)

**Problem:** Users may want to switch between Docker and embedded modes; no migration path exists.

**Implementation:**

1. **Design migration architecture** [1-1.5 hours]
   - Migration directions:
     - **Docker → Embedded:** Export from Docker, import to embedded
     - **Embedded → Docker:** Export from embedded, import to Docker
   - Data to migrate:
     - Documents (ChromaDB collections)
     - Embeddings (vectors)
     - Metadata (document info, collections)
     - Configuration (settings, secrets)
   - Migration strategies:
     - **Direct:** Copy database files (if compatible)
     - **Export/Import:** JSON dump → load

2. **Implement Docker → Embedded migration** [1-1.5 hours]
   - Export data from Docker ChromaDB:
     ```python
     # Connect to Docker ChromaDB
     docker_client = chromadb.HttpClient(host="localhost", port=8001)
     collection = docker_client.get_collection("ragged")

     # Get all documents
     all_docs = collection.get()

     # Export to JSON
     export_data = {
         "documents": all_docs["documents"],
         "embeddings": all_docs["embeddings"],
         "metadatas": all_docs["metadatas"],
         "ids": all_docs["ids"],
     }
     with open("~/ragged-export.json", "w") as f:
         json.dump(export_data, f)
     ```
   - Import to embedded ChromaDB:
     ```python
     # Connect to embedded ChromaDB
     embedded_client = chromadb.PersistentClient(path="~/.ragged/chromadb")
     collection = embedded_client.create_collection("ragged")

     # Load export
     with open("~/ragged-export.json", "r") as f:
         import_data = json.load(f)

     # Import documents
     collection.add(
         documents=import_data["documents"],
         embeddings=import_data["embeddings"],
         metadatas=import_data["metadatas"],
         ids=import_data["ids"],
     )
     ```
   - Verify migration: Query test document

3. **Implement Embedded → Docker migration** [0.5-1 hour]
   - Reverse of above
   - Export from embedded, import to Docker
   - Start Docker container before import

4. **Add migration CLI command** [0.5-1 hour]
   - `ragged migrate --from docker --to embedded`
   - `ragged migrate --from embedded --to docker`
   - Backup before migration (safety)
   - Rollback if migration fails

**Files:**
- `src/database/migration.py` (new - mode migration, ~300 lines)
- `src/cli/commands/migrate.py` (new - migrate CLI, ~150 lines)
- `tests/database/test_migration.py` (new - migration tests, ~250 lines)

**Success Criteria:**
- Migration succeeds (Docker ↔ embedded)
- Data preserved (documents, embeddings, metadata)
- Queries work after migration
- Rollback works if migration fails
- Migration time reasonable (<5 minutes for 1000 docs)

## Known Risks

- **SQLite limitations:** File locking issues on Windows, single-writer limitation (mitigate: document limitations, warn users)
- **Performance degradation:** Embedded mode may be slower (mitigate: optimise, set expectations)
- **Less isolation:** ChromaDB crash affects ragged (mitigate: robust error handling, automatic restarts)
- **Migration complexity:** Docker ↔ embedded migration may fail (mitigate: backups, rollback, extensive testing)
