# Ragged v0.7.2 Roadmap - WebUI Advanced Visualisations

**Status:** Planned

**Total Hours:** 30-40 hours (AI implementation)

**Focus:** Enhanced knowledge exploration through advanced data visualisations

**Breaking Changes:** None

**Dependencies:** Requires v0.7.1 completion (WebUI feature completeness), builds on v0.6.9 (knowledge graph)

**Purpose:** Transform knowledge base from "searchable database" to "explorable knowledge network"

---

## Overview

Version 0.7.2 extends the visualisation capabilities introduced in v0.6.9 (interactive knowledge graph, GPU monitoring) with six advanced visualisation features that enable deeper knowledge exploration, system insights, and performance analytics. These visualisations leverage D3.js, Three.js, and modern WebGL techniques to create interactive, informative data views.

### Problem Statement

**Current Visualisation Limitations:**
- Knowledge graph (v0.6.9) shows document connections but not detailed similarity analysis
- No query performance analytics (cannot track system performance over time)
- Storage analytics missing (unclear where disk space is used)
- No model performance comparison (cannot evaluate different LLM models)
- Cache effectiveness invisible (don't know if caching improves performance)
- Embedding space unexplored (high-dimensional semantic space inaccessible)

### Target Outcomes

**After v0.7.2 Implementation:**
- ✅ Interactive document similarity network graph
- ✅ Query performance trends (latency, throughput over time)
- ✅ Storage analytics dashboard (disk usage breakdown, growth projections)
- ✅ Model performance comparison UI (accuracy, speed, cost trade-offs)
- ✅ Cache effectiveness visualisation (hit rate, memory usage)
- ✅ Embedding space exploration (3D projection, semantic clusters)

## VIZ-001: Document Similarity Network Graph (6-8 hours)

**Problem:** Knowledge graph (v0.6.9) shows document relationships but not similarity strength or clusters.

**Implementation:**

1. **Design similarity graph layout** [2-2.5 hours]
   - Force-directed graph with similarity-based edge weights:
     - Nodes: Documents (size = document length, colour = type)
     - Edges: Cosine similarity >0.7 (thickness = similarity strength)
     - Clusters: Automatically detect communities (Louvain algorithm)
   - Interactive features:
     - Zoom, pan, rotate (3D mode optional)
     - Click document to highlight connections
     - Filter by similarity threshold
     - Search and centre on document
   - Layout algorithms:
     - Force-directed (default)
     - Hierarchical (for document hierarchies)
     - Circular (for specific collections)

2. **Implement similarity calculation** [2-3 hours]
   - Backend API endpoint: `GET /analytics/document-similarity`
   - Calculate pairwise cosine similarity for embeddings
   - Filter edges by similarity threshold (configurable)
   - Detect communities using NetworkX or igraph
   - Cache similarity matrix (expensive computation)

3. **Create graph visualisation UI** [1.5-2 hours]
   - D3.js force simulation for layout
   - WebGL rendering for large graphs (>1000 nodes)
   - Sidebar panel showing selected document info
   - Controls: similarity threshold slider, layout selection
   - Export graph as PNG/SVG

4. **Add similarity insights** [0.5-1 hour]
   - Detect document clusters: "5 clusters identified"
   - Find isolated documents: "12 documents have no similar matches"
   - Suggest document merging: "Documents X and Y are 95% similar"
   - Highlight duplicate detection

**Files:**
- `src/webui/components/visualisations/SimilarityGraph.svelte` (new)
- `src/web/routes/analytics.py` (new - analytics API endpoints)
- `src/analytics/similarity.py` (new - similarity calculation)

**⚠️ MANUAL TEST:** Generate graph with 100+ documents, verify performance, test interactions

**Success Criteria:**
- Graph renders smoothly (>30 FPS for 1000 documents)
- Similarity calculations accurate (manually verify samples)
- Community detection identifies logical clusters
- Interactive exploration intuitive

## VIZ-002: Query Performance Trends Over Time (5-7 hours)

**Problem:** No visibility into query performance trends; cannot detect degradation or optimise.

**Implementation:**

1. **Design performance dashboard** [1.5-2 hours]
   - Time-series charts showing:
     - Query latency (p50, p95, p99) over time
     - Query throughput (queries per minute)
     - Document retrieval count distribution
     - Error rate (failed queries %)
   - Date range selector (last hour, day, week, month, custom)
   - Overlays for events (document ingestion, model changes)
   - Annotations for performance incidents

2. **Implement performance metrics collection** [2-3 hours]
   - Extend query history (v0.7.1) to include performance metrics
   - Schema: `{query_id, timestamp, latency_ms, result_count, model, success}`
   - Backend API: `GET /analytics/query-performance?range=7d`
   - Aggregate metrics by hour/day for long time ranges
   - Detect anomalies (latency >2x average)

3. **Create interactive charts** [1-1.5 hours]
   - Use Chart.js or D3.js for time-series plots
   - Brushing and linking: Select time range in one chart, updates others
   - Hover tooltips showing exact values
   - Downloadable as CSV for external analysis

4. **Add performance insights** [0.5-1 hour]
   - Automatic insights: "Query latency increased 40% this week"
   - Correlations: "Latency spike correlates with document ingestion"
   - Recommendations: "Consider upgrading to faster LLM model"

**Files:**
- `src/webui/components/visualisations/QueryPerformance.svelte` (new)
- `src/analytics/query_performance.py` (new - performance analytics)
- `src/database/query_history.py` (modify - add performance metrics)

**⚠️ MANUAL TEST:** Run queries over several days, verify trends accurate, test anomaly detection

**Success Criteria:**
- Metrics collected for all queries
- Charts update in real-time (<1s refresh)
- Anomaly detection identifies actual issues
- Insights actionable

## VIZ-003: Storage Analytics Dashboard (4-6 hours)

**Problem:** Users don't know where disk space is used; cannot optimise storage or predict capacity needs.

**Implementation:**

1. **Design storage breakdown UI** [1-1.5 hours]
   - Sunburst chart or treemap showing storage distribution:
     - Documents (by type: PDF, Markdown, code, etc.)
     - Embeddings (ChromaDB database)
     - Models (Ollama downloads)
     - Cache (temporary files)
     - Logs (ragged logs, service logs)
   - Interactive drill-down (click to zoom into category)
   - Storage over time trend (historical growth)

2. **Implement storage analysis backend** [2-3 hours]
   - Backend API: `GET /analytics/storage`
   - Scan filesystem for ragged-related files:
     - `~/.ragged/documents/`
     - `~/.ragged/chromadb/`
     - `~/.ollama/models/`
     - `~/.ragged/cache/`
     - `~/.ragged/logs/`
   - Calculate sizes, file counts, last modified
   - Cache results (expensive operation, refresh every hour)

3. **Add growth projections** [0.5-1 hour]
   - Linear regression on historical storage data
   - Predict when disk will be full
   - Warn if < 10% disk space remaining
   - Suggest cleanup actions

4. **Create cleanup suggestions** [0.5-1 hour]
   - Identify large, old files: "5GB of logs >30 days old"
   - Suggest model removals: "Remove unused models to free 12GB"
   - Cache cleanup: "Clear cache to free 2.5GB"
   - One-click cleanup actions

**Files:**
- `src/webui/components/visualisations/StorageAnalytics.svelte` (new)
- `src/analytics/storage.py` (new - storage analysis)
- `src/maintenance/cleanup.py` (new - cleanup actions)

**⚠️ MANUAL TEST:** Verify storage calculations accurate, test cleanup actions

**Success Criteria:**
- Storage breakdown accurate (within 5% of actual)
- Drill-down works smoothly
- Growth projections reasonable (validated over weeks)
- Cleanup actions safe (no accidental deletion)

## VIZ-004: Model Performance Comparison UI (5-7 hours)

**Problem:** Cannot compare LLM models objectively; unclear which model to use for specific tasks.

**Implementation:**

1. **Design model comparison dashboard** [1.5-2 hours]
   - Radar chart comparing models across dimensions:
     - Accuracy (user-rated query quality)
     - Speed (average query latency)
     - Cost (computational resources)
     - Context window (max tokens)
     - Capabilities (code, math, general)
   - Side-by-side query results comparison
   - Performance metrics table

2. **Implement model benchmarking** [2-3 hours]
   - Backend API: `GET /analytics/model-performance`
   - Store per-model metrics in database:
     - Query count, average latency, error rate
     - User satisfaction ratings (thumbs up/down)
     - Token usage (if available from Ollama)
   - Benchmark suite: Run standard queries across models
   - Schema: `{model_name, query_count, avg_latency_ms, satisfaction_rate, ...}`

3. **Add A/B testing capability** [1-1.5 hours]
   - Run same query on multiple models
   - Display results side-by-side
   - User selects preferred result (trains preference model)
   - Aggregate preferences to recommend models

4. **Create model recommendations** [0.5-1 hour]
   - Analyse user's query patterns
   - Recommend optimal model based on:
     - Query type (code, research, general)
     - Latency requirements (fast vs accurate)
     - Disk space constraints (model size)

**Files:**
- `src/webui/components/visualisations/ModelComparison.svelte` (new)
- `src/analytics/model_performance.py` (new - model analytics)
- `src/models/benchmarking.py` (new - model benchmarks)

**⚠️ MANUAL TEST:** Compare models across various queries, verify metrics accurate

**Success Criteria:**
- Metrics reflect actual model behaviour
- Radar chart clearly shows trade-offs
- A/B testing provides useful comparisons
- Recommendations improve over time

## VIZ-005: Cache Effectiveness Visualisation (4-5 hours)

**Problem:** Cache hit rates invisible; cannot optimise caching strategy or measure performance gains.

**Implementation:**

1. **Design cache metrics dashboard** [1-1.5 hours]
   - Metrics cards:
     - Cache hit rate (%): "78% of queries served from cache"
     - Average latency reduction: "Cache saves 420ms per query"
     - Cache size: "2.3GB / 5.0GB (46% full)"
     - Eviction rate: "15 evictions per hour"
   - Time-series charts:
     - Hit rate over time
     - Cache size growth
     - Memory usage

2. **Implement cache instrumentation** [1.5-2 hours]
   - Add cache metrics to existing cache layer:
     - Track hits, misses, evictions
     - Measure latency with/without cache
     - Monitor memory usage
   - Backend API: `GET /analytics/cache-performance`
   - Store metrics in time-series database or aggregate hourly

3. **Add cache optimisation insights** [0.5-1 hour]
   - Detect suboptimal cache settings:
     - "Hit rate low (45%), consider increasing cache size"
     - "Eviction rate high, increase TTL or cache capacity"
   - Suggest cache warming for frequent queries
   - Identify cache-unfriendly query patterns

4. **Create cache management UI** [0.5-1 hour]
   - Clear cache button (with confirmation)
   - Adjust cache size/TTL from UI
   - Manually warm cache for specific documents

**Files:**
- `src/webui/components/visualisations/CacheAnalytics.svelte` (new)

## VIZ-006: Embedding Space Exploration (6-8 hours)

**Problem:** High-dimensional embedding space invisible; cannot explore semantic relationships or detect outliers.

**Implementation:**

1. **Design 3D embedding projection** [2-2.5 hours]
   - Dimensionality reduction (UMAP or t-SNE):
     - Project 1536-D embeddings to 3D space
     - Preserve local structure (similar documents cluster)
   - 3D scatter plot using Three.js or Plotly:
     - Points: Documents (colour by type, size by length)
     - Hover: Document title and snippet
     - Click: Highlight similar documents
   - Camera controls: Rotate, zoom, pan

2. **Implement dimensionality reduction** [2-3 hours]
   - Backend API: `GET /analytics/embedding-projection?method=umap`
   - Use UMAP (preferred) or t-SNE for reduction
   - Cache projections (expensive computation)
   - Support multiple projection methods for comparison
   - Incremental updates (new documents added to projection)

3. **Add semantic cluster analysis** [1-1.5 hours]
   - Detect clusters in reduced space (DBSCAN or K-means)
   - Label clusters by common themes:
     - Extract keywords from cluster documents
     - Display as word cloud or tag list
   - Outlier detection (documents far from any cluster)

4. **Create exploration features** [0.5-1 hour]
   - Search and highlight documents in 3D space
   - Filter by metadata (show only PDFs, etc.)
   - Trajectory view: Show query path through semantic space
   - Export projection as CSV for external analysis

**Files:**
- `src/webui/components/visualisations/EmbeddingSpace.svelte` (new)
- `src/analytics/dimensionality_reduction.py` (new - UMAP/t-SNE)
- `src/analytics/clustering.py` (new - cluster detection)

**⚠️ MANUAL TEST:** Project 500+ documents, verify clusters logical, test performance

**Success Criteria:**
- Projection preserves semantic structure (similar docs cluster)
- 3D visualisation smooth (>30 FPS)
- Clusters correspond to logical themes

## Known Risks

- **Computation cost:** Dimensionality reduction expensive for large datasets (mitigate: caching, background processing)
- **Accuracy:** Similarity metrics may not reflect user's semantic understanding (mitigate: user feedback)
- **Visualisation complexity:** Advanced charts may confuse non-technical users (mitigate: tooltips, tutorials)
- **Browser performance:** WebGL rendering may struggle on older hardware (mitigate: fallback to 2D, progressive rendering)
