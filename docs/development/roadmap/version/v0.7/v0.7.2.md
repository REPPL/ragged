# Ragged v0.7.2 Roadmap - Platform-Specific Enhancements & Native Installers

**Status:** Planned (conditional on user demand)

**Total Hours:** 20-30 hours (AI implementation)

**Focus:** Professional native installers for all major platforms

**Breaking Changes:** None

**Dependencies:** Requires v0.7.1 completion, implement only if demand exists

**Purpose:** Transform ragged from "developer tool" to "professional software" with native platform installers

---

## Overview

Version 0.7.2 provides native installers for macOS, Windows, and Linux, eliminating the need for command-line installation. Whilst v0.7.0's script-based approach works well for developers, professional users and enterprises often expect double-click installers that integrate with their operating system.

**Rationale:** Native installers signal maturity and professionalism, making ragged more accessible to non-developer users and suitable for enterprise deployment.

---

## Decision Criteria

### Implement v0.7.2 if:

**User demand indicators:**
- ✓ GitHub issues request native installers (>10 independent requests)
- ✓ Installation analytics show script friction (>20% abandon during CLI installation)
- ✓ Enterprise adoption feedback explicitly requests DMG/MSI/DEB packages
- ✓ Community polls/votes strongly favour native installers

**Market signals:**
- ✓ Competitors offer native installers (need parity)
- ✓ Target users include non-developers (less CLI-comfortable)
- ✓ Enterprise customers require standard deployment methods

### Skip v0.7.2 if:

**Counter-indicators:**
- ✗ Script-based installation proves sufficient (<5% abandonment rate)
- ✗ User community satisfied with CLI method (<5 installer requests)
- ✗ Resources better spent on v0.8 advanced features
- ✗ Maintenance burden (three installers + script) outweighs benefits

### Decision Point

**When:** After v0.7.1 release and 2-3 weeks of feedback collection

**How:** Review GitHub issues, installation analytics, user surveys, enterprise feedback

## PLATFORM-001: macOS DMG Installer (8-12 hours)

**Problem:** macOS users expect drag-and-drop `.app` installation, not command-line scripts.

**Implementation:**

1. **Design macOS application bundle** [2-3 hours]
   - Create `.app` bundle structure:
     ```
     ragged.app/
     ├── Contents/
     │   ├── Info.plist (bundle metadata)
     │   ├── MacOS/
     │   │   └── ragged (launcher script)
     │   ├── Resources/
     │   │   ├── icon.icns
     │   │   ├── python/ (bundled Python 3.12)
     │   │   └── ragged/ (ragged source)
     │   └── Frameworks/ (dependencies)
     ```
   - Launcher script handles:
     - Python virtual environment setup
     - Dependency installation
     - PATH configuration
     - First-run setup
   - Design application icon (ragged logo)

2. **Implement code signing and notarisation** [3-4 hours]
   - **Requirement:** Apple Developer Account ($99/year)
   - **Code signing:**
     - Sign `.app` bundle with Developer ID certificate
     - Enable hardened runtime
     - Sign all binaries and frameworks
   - **Notarisation:**
     - Upload to Apple's notary service
     - Wait for approval (automated, ~5 minutes)
     - Staple notarisation ticket to DMG
   - **Result:** Passes Gatekeeper (no "unidentified developer" warning)

3. **Create DMG disk image** [1.5-2 hours]
   - Design DMG window:
     - Background image with ragged branding
     - Drag ragged.app to Applications folder
     - Optional: Include README and documentation links
   - Use `create-dmg` tool for automated generation
   - Set DMG metadata (license, icon)

4. **Add Homebrew integration** [1-1.5 hours]
   - Homebrew formula automatically installs dependencies:
     - Ollama: `brew install ollama`
     - Docker: `brew install --cask docker`
     - Poppler: `brew install poppler`
   - Formula triggers post-install setup
   - Add to Homebrew tap: `brew tap REPPL/ragged`
   - Install command: `brew install --cask ragged`

5. **Add menu bar integration** [0.5-1 hour]
   - Menu bar icon for quick access
   - Menu items:
     - "Open ragged Terminal"
     - "Check Health"
     - "Preferences"
     - "Documentation"
     - "Quit ragged Services"
   - Start/stop Ollama and ChromaDB from menu bar

**Files:**
- `installers/macos/ragged.app/` (new - application bundle)
- `installers/macos/ragged.icns` (new - application icon)
- `installers/macos/build-dmg.sh` (new - DMG creation script)
- `installers/macos/homebrew-formula.rb` (new - Homebrew formula)
- `installers/macos/menu-bar.py` (new - menu bar integration)

**⚠️ MANUAL TEST:**
- Install DMG on fresh macOS system
- Verify no Gatekeeper warnings
- Test drag-and-drop to Applications
- Verify menu bar integration works
- Test uninstaller

**Success Criteria:**
- DMG passes Gatekeeper without warnings
- Installation time <5 minutes (faster than script)
- Automatic dependency installation (Homebrew)
- Menu bar provides convenient access
- Uninstaller removes all files cleanly
- >40% of macOS users choose DMG over script

## PLATFORM-002: Windows MSI Installer (8-12 hours)

**Problem:** Windows users expect `.msi` or `.exe` installers with Start Menu integration, not PowerShell scripts.

**Implementation:**

1. **Design MSI package using WiX Toolset** [3-4 hours]
   - Install WiX Toolset (open-source Windows installer framework)
   - Create WiX XML manifest:
     ```xml
     <Product Id="*" Name="ragged" Version="0.7.2" ...>
       <Package InstallerVersion="500" Compressed="yes" />
       <Media Id="1" Cabinet="ragged.cab" EmbedCab="yes" />

       <Directory Id="TARGETDIR" Name="SourceDir">
         <Directory Id="ProgramFiles64Folder">
           <Directory Id="INSTALLFOLDER" Name="ragged">
             <!-- Components: Python, ragged, dependencies -->
           </Directory>
         </Directory>
         <Directory Id="ProgramMenuFolder">
           <Directory Id="ApplicationProgramsFolder" Name="ragged" />
         </Directory>
       </Directory>

       <!-- Features: Core, Documentation, Examples -->
       <!-- Registry keys, PATH modification, shortcuts -->
     </Product>
     ```
   - Define features: Core (required), Documentation (optional), Examples (optional)

2. **Add PATH configuration** [1-1.5 hours]
   - Add ragged to system PATH during installation
   - Modify user PATH (non-admin) or system PATH (admin)
   - Verify PATH changes take effect
   - Remove from PATH on uninstall

3. **Create Start Menu shortcuts** [1-1.5 hours]
   - Start Menu folder: `Programs/ragged/`
   - Shortcuts:
     - "ragged CLI" - Opens terminal with ragged activated
     - "ragged Health Check" - Runs `ragged health`
     - "ragged Documentation" - Opens docs in browser
     - "Uninstall ragged" - Launches uninstaller
   - Add ragged icon to all shortcuts

4. **Add dependency installation** [2-3 hours]
   - Check for dependencies during installation:
     - Python 3.12 (bundle if missing)
     - Docker Desktop (prompt to install)
     - Ollama (download and install)
   - Use Windows Installer Custom Actions for checks
   - Provide fallback: manual installation links if automated fails

5. **Create uninstaller** [0.5-1 hour]
   - MSI automatically generates uninstaller
   - Available via Control Panel > Programs and Features
   - Custom uninstall actions:
     - Stop ragged services
     - Remove PATH entries
     - Clean up user data (optional, ask user)
   - Leave user documents by default

**Files:**
- `installers/windows/ragged.wxs` (new - WiX manifest)
- `installers/windows/ragged.ico` (new - Windows icon)
- `installers/windows/build-msi.ps1` (new - PowerShell build script)
- `installers/windows/custom-actions.dll` (new - WiX custom actions)

**⚠️ MANUAL TEST:**
- Install MSI on fresh Windows 10/11 system
- Verify no Windows Defender warnings
- Test PATH configuration (open new terminal, run `ragged`)
- Verify Start Menu shortcuts work
- Test uninstaller via Control Panel

**Success Criteria:**
- MSI installs without admin rights (user-level install)
- PATH automatically configured
- Start Menu integration complete
- Dependency installation automated (or clearly prompted)
- Uninstaller removes all files cleanly
- Windows Defender compatible (no false positives)
- >40% of Windows users choose MSI over script

## PLATFORM-003: Linux DEB/RPM Packages (4-6 hours)

**Problem:** Linux users expect native packages (DEB for Debian/Ubuntu, RPM for Fedora/RHEL) for system integration.

**Implementation:**

1. **Create Debian package (.deb)** [2-3 hours]
   - Use `dpkg-deb` to create package structure:
     ```
     ragged_0.7.2_amd64.deb
     └── DEBIAN/
         ├── control (package metadata)
         ├── postinst (post-installation script)
         ├── prerm (pre-removal script)
         ├── postrm (post-removal script)
         └── conffiles (configuration files)
     └── usr/
         ├── bin/
         │   └── ragged (symlink to /opt/ragged/bin/ragged)
         ├── share/
         │   ├── applications/
         │   │   └── ragged.desktop (desktop entry)
         │   ├── doc/
         │   │   └── ragged/ (documentation)
         │   └── icons/
         │       └── ragged.png (application icon)
         └── lib/
             └── systemd/system/
                 ├── ragged-ollama.service
                 └── ragged-chromadb.service
     ```
   - Control file defines:
     - Package name, version, architecture
     - Dependencies: `python3.12`, `docker.io`, `poppler-utils`
     - Maintainer, description, homepage
   - Post-installation script:
     - Create ragged user and group (if system-wide)
     - Set up virtual environment
     - Install Python dependencies
     - Enable systemd services (optional)

2. **Create RPM package (.rpm)** [2-3 hours]
   - Use `rpmbuild` with spec file:
     ```
     ragged-0.7.2-1.x86_64.rpm
     └── SPECS/
         └── ragged.spec
     ```
   - Spec file defines:
     - Package metadata (Name, Version, Release)
     - Build requirements and runtime dependencies
     - %prep, %build, %install, %files sections
     - %post (post-install), %preun (pre-uninstall) scripts
   - Similar structure to DEB but RPM conventions

3. **Add systemd service integration** [1-1.5 hours]
   - Create systemd unit files:
     ```ini
     [Unit]
     Description=ragged Ollama Service
     After=network.target

     [Service]
     Type=simple
     User=ragged
     ExecStart=/usr/bin/ollama serve
     Restart=on-failure

     [Install]
     WantedBy=multi-user.target
     ```
   - Services:
     - `ragged-ollama.service` - Ollama LLM server
     - `ragged-chromadb.service` - ChromaDB vector database
   - Enable on installation: `systemctl enable ragged-ollama`
   - User can control: `systemctl start/stop/status ragged-ollama`

4. **Add desktop entry** [0.5-1 hour]
   - Create `.desktop` file for application menu:
     ```ini
     [Desktop Entry]
     Name=ragged
     Comment=Privacy-first RAG system
     Exec=/usr/bin/ragged
     Icon=ragged
     Terminal=true
     Type=Application
     Categories=Development;Education;
     ```
   - Appears in application menu (GNOME, KDE, etc.)
   - Launches terminal with ragged CLI

**Files:**
- `installers/linux/debian/control` (new)
- `installers/linux/debian/postinst` (new)
- `installers/linux/rpm/ragged.spec` (new)
- `installers/linux/systemd/ragged-ollama.service` (new)
- `installers/linux/systemd/ragged-chromadb.service` (new)
- `installers/linux/ragged.desktop` (new)
- `scripts/build-deb.sh` (new)
- `scripts/build-rpm.sh` (new)

**⚠️ MANUAL TEST:**
- Install DEB on Ubuntu 22.04/24.04
- Install RPM on Fedora 38/39
- Verify dependencies installed automatically
- Test systemd services (start/stop/status)
- Verify desktop entry appears in application menu
- Test uninstall via `apt remove ragged` / `dnf remove ragged`

**Success Criteria:**
- DEB installs on Debian, Ubuntu, Linux Mint
- RPM installs on Fedora, RHEL, CentOS
- Dependencies handled automatically
- Systemd services start/stop correctly
- Desktop integration complete
- Uninstall removes all files cleanly
- >30% of Linux users choose DEB/RPM over script

## Known Risks

- **Code signing costs:** Apple Developer Account ($99/year), Windows code signing certificate (~$200-400/year)
- **Platform fragmentation:** Linux distributions vary (Arch, openSUSE, etc.)
- **Maintenance burden:** Three installers + script = four installation paths to support
- **Update mechanism:** Native installers may need auto-update capability (defer to v0.8?)
- **Dependency conflicts:** System-installed Python/Docker may conflict with ragged requirements

## Implementation Notes

### Prerequisites for v0.7.2 Development

**Required:**
- Apple Developer Account (macOS code signing)
- Windows code signing certificate (optional but recommended)
- Test VMs for each platform (macOS 12-14, Windows 10-11, Ubuntu 20.04-24.04, Fedora 38-39)
- WiX Toolset (Windows)
- `create-dmg` tool (macOS)
- `dpkg-deb`, `rpmbuild` (Linux)

**Time investment beyond implementation hours:**
- Certificate procurement: 1-2 days
- VM setup: 1 day
- Learning WiX/packaging tools: 2-3 days (if unfamiliar)

### Alternative: Third-Party Installer Services

Consider using third-party services to reduce implementation burden:
- **InstallBuilder** - Cross-platform installer creation (commercial, ~$600)
- **Electron Forge** - If ragged adds Electron wrapper (future)
- **Flatpak/Snap** - Universal Linux packages (complementary to DEB/RPM)

**Trade-off:** Lower maintenance burden but ongoing costs and less control.
