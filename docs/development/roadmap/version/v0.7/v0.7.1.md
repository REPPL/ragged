# Ragged v0.7.1 Roadmap - WebUI Feature Completeness

**Status:** Planned

**Total Hours:** 35-50 hours (AI implementation)

**Focus:** Fill critical feature gaps in WebUI to achieve parity with desktop RAG applications

**Breaking Changes:** None

**Dependencies:** Requires v0.7.0 completion (CLI UX & WebUI integration)

**Purpose:** Transform WebUI from "functional prototype" to "feature-complete application"

---

## Overview

Version 0.7.1 addresses feature gaps in the Svelte WebUI delivered in v0.6.7-v0.6.10. Whilst v0.6 established the technical foundation (document management, basic queries, visualisations), many essential features expected in modern applications are missing. This release implements 10 critical features to achieve feature parity with desktop RAG applications and commercial alternatives.

### Problem Statement

**Current WebUI Limitations:**
- No advanced query filtering (by date, source, type, metadata)
- Documents lack organisation (no collections, tags, categories)
- No query history (cannot review or repeat past queries)
- No bulk operations (cannot delete/tag multiple documents at once)
- No user preferences panel (settings buried in config files)
- No keyboard shortcuts (mouse-only interaction)
- Error boundaries missing (app crashes on errors)
- Loading states inconsistent (unclear when operations in progress)
- Empty states generic (no helpful guidance when collections empty)
- No integrated help (users must leave app to read documentation)

### Target Outcomes

**After v0.7.1 Implementation:**
- ✅ Advanced query filters (date range, document type, metadata facets)
- ✅ Document collections and tags (organise knowledge base)
- ✅ Complete query history with repeat/edit capabilities
- ✅ Bulk operations (select multiple, batch actions)
- ✅ User preferences panel (all settings in UI)
- ✅ Comprehensive keyboard shortcuts (power-user efficiency)
- ✅ Graceful error handling (app never crashes)
- ✅ Professional loading states (skeleton screens, progress indicators)
- ✅ Helpful empty states (onboarding, suggestions)
- ✅ Integrated help overlay (contextual documentation)

## WEB-001: Advanced Query Filters & Facets UI (4-6 hours)

**Problem:** Users cannot filter query results by date, document type, or metadata; must manually scan all results.

**Implementation:**

1. **Design filter panel UI** [1-1.5 hours]
   - Create filter sidebar in query interface:
     - Date range picker (last 7 days, 30 days, custom range)
     - Document type filter (PDF, Markdown, TXT, DOCX, code files)
     - Source filter (by directory, file path patterns)
     - Metadata facets (auto-generated from document metadata)
   - Collapsible filter groups with counts
   - "Active Filters" chips showing applied filters
   - "Clear All" and individual filter removal

2. **Implement filter state management** [1.5-2 hours]
   - Svelte store for filter state
   - URL query parameters for shareable filtered queries
   - Filter persistence in localStorage
   - Filter validation and sanitisation

3. **Integrate with backend API** [1-1.5 hours]
   - Modify FastAPI query endpoint to accept filter parameters
   - ChromaDB query modification with where clauses
   - Efficient filtering without full result set retrieval
   - Return facet counts (e.g., "23 PDFs, 12 Markdown")

4. **Add filter presets** [0.5-1 hour]
   - Common filter combinations saved as presets:
     - "Recent documents" (last 7 days)
     - "Code files only"
     - "Research papers" (PDF + academic metadata)
   - User-defined custom presets

**Files:**
- `src/webui/components/QueryFilters.svelte` (new)
- `src/webui/stores/filters.ts` (new)
- `src/web/api.py` (modify - add filter parameters to query endpoint)
- `src/retrieval/filters.py` (new - filter logic)

**⚠️ MANUAL TEST:** Apply filters, verify results match criteria, test URL sharing

**Success Criteria:**
- Filters reduce result set accurately
- Filter combinations work correctly (AND logic)
- Shareable URLs preserve filters
- Performance: Filtered queries <200ms (10k documents)

## WEB-002: Document Collections & Organisation UI (5-7 hours)

**Problem:** All documents in single flat list; no way to organise knowledge base into topics, projects, or categories.

**Implementation:**

1. **Design collections UI** [1.5-2 hours]
   - Collections sidebar with tree structure:
     - Create, rename, delete collections
     - Drag-and-drop documents into collections
     - Nested collections (subcollections)
     - Collection icons and colors
   - Document can belong to multiple collections (tags)
   - "Uncategorised" default collection

2. **Implement collections data model** [2-3 hours]
   - Backend: Store collections in ChromaDB metadata
   - Collection schema: `{id, name, parent_id, color, icon, created_at}`
   - Document-collection relationships (many-to-many)
   - API endpoints:
     - `POST /collections` - Create collection
     - `GET /collections` - List all collections
     - `PUT /collections/{id}` - Update collection
     - `DELETE /collections/{id}` - Delete collection
     - `POST /collections/{id}/documents` - Add documents

3. **Create collection management UI** [1-1.5 hours]
   - Collection browser with search
   - Bulk add documents to collection (select multiple)
   - Collection statistics (document count, last updated)
   - Smart collections (auto-categorise by metadata)

4. **Add collection-based filtering** [0.5-1 hour]
   - Filter query results by collection
   - "Search within collection" mode
   - Collection-based document listing

**Files:**
- `src/webui/components/CollectionsSidebar.svelte` (new)
- `src/webui/components/CollectionManager.svelte` (new)
- `src/web/routes/collections.py` (new - collection API endpoints)
- `src/database/collections.py` (new - collection data model)

**⚠️ MANUAL TEST:** Create collections, add documents, verify filtering, test nested collections

**Success Criteria:**
- Collections organise documents intuitively
- Drag-and-drop works smoothly
- Nested collections supported
- Performance: Collections load <100ms (1000 collections)

## WEB-003: Query History Management UI (4-6 hours)

**Problem:** No record of past queries; users must re-type queries, cannot compare results over time.

**Implementation:**

1. **Design query history UI** [1-1.5 hours]
   - History sidebar showing recent queries:
     - Query text, timestamp, result count
     - Click to repeat query
     - Edit and re-run queries
     - Star favourite queries
   - History search (filter by keyword, date)
   - Group by date (today, yesterday, last 7 days)

2. **Implement history storage** [1.5-2 hours]
   - Backend: Store query history in SQLite database
   - Schema: `{id, query_text, timestamp, result_count, filters, starred}`
   - API endpoints:
     - `GET /query-history` - List recent queries
     - `POST /query-history/{id}/repeat` - Repeat query
     - `PUT /query-history/{id}/star` - Star query
     - `DELETE /query-history/{id}` - Delete from history
   - Privacy: Optional local-only storage

3. **Add query comparison** [1-1.5 hours]
   - Select two queries to compare results
   - Side-by-side diff view
   - Highlight documents unique to each query
   - Useful for tracking knowledge base changes

4. **Create history export** [0.5-1 hour]
   - Export history as CSV/JSON
   - Include query, timestamp, results
   - Useful for research documentation

**Files:**
- `src/webui/components/QueryHistory.svelte` (new)
- `src/webui/components/QueryComparison.svelte` (new)
- `src/web/routes/history.py` (new - query history API)
- `src/database/query_history.py` (new - history data model)

**⚠️ MANUAL TEST:** Run queries, verify history saved, test repeat/edit/compare features

**Success Criteria:**
- All queries automatically saved to history
- Repeat query works with original filters
- Starred queries easily accessible
- Privacy: History deletable/disableable

## WEB-005: User Preferences & Settings Panel (4-6 hours)

**Problem:** Settings buried in .env files; users must edit configuration manually, no UI for preferences.

**Implementation:**

1. **Design settings panel** [1-1.5 hours]
   - Settings modal with tabs:
     - **General:** Theme, language, timezone
     - **Query:** Default filters, result count, reranking
     - **Documents:** Default collection, auto-index, file types
     - **Privacy:** Telemetry, query history, analytics
     - **Advanced:** API keys, model selection, GPU settings

2. **Implement settings backend** [2-3 hours]

     - `PUT /settings` - Update settings

3. **Add settings reactivity** [0.5-1 hour]
   - Changes apply immediately (no page reload)
   - Preview changes before saving (where applicable)
   - Toast confirmation: "Settings saved"

4. **Create keyboard shortcuts panel** [0.5-1 hour]
   - Embedded in settings: "Keyboard Shortcuts" tab
   - List all shortcuts with customisation
   - Shortcut conflict detection
   - Export/import shortcut configurations

**Files:**

## WEB-006: Comprehensive Keyboard Shortcuts UI (3-4 hours)

**Problem:** WebUI is mouse-only; power users cannot navigate efficiently with keyboard.

**Implementation:**

1. **Define keyboard shortcut schema** [1-1.5 hours]
   - Global shortcuts:
     - `Ctrl+K` or `Cmd+K`: Command palette (search all actions)
     - `/`: Focus search/query input
     - `Ctrl+H`: Toggle history sidebar
     - `Ctrl+F`: Toggle filter sidebar
     - `?`: Show keyboard shortcuts help
   - Document list shortcuts:
     - `j`/`k`: Navigate documents (vim-style)
     - `Space`: Select document
     - `Enter`: Open document
     - `Delete`: Delete selected documents
   - Query shortcuts:
     - `Ctrl+Enter`: Submit query
     - `Ctrl+L`: Clear query input
     - `Esc`: Cancel query

2. **Implement shortcut system** [1-1.5 hours]
   - Svelte action for key binding: `use:shortcut`
   - Global keyboard event listener
   - Context-aware shortcuts (different shortcuts per view)
   - Shortcut conflict resolution

3. **Create command palette** [0.5-1 hour]
   - Fuzzy searchable command list (like VS Code)
   - Access all actions via keyboard:
     - "Create collection"
     - "Import documents"
     - "Export query results"
     - "Open settings"
   - Recent commands prioritised

**Files:**
- `src/webui/lib/shortcuts.ts` (new - shortcut system)
- `src/webui/components/CommandPalette.svelte` (new)
- `src/webui/components/KeyboardShortcutsHelp.svelte` (new)

**⚠️ MANUAL TEST:** Test all shortcuts, verify no conflicts, test command palette

**Success Criteria:**
- All common actions have keyboard shortcuts
- Shortcuts work consistently across browsers
- Command palette provides access to all features
- Shortcut help easily discoverable (`?`)

## WEB-007: Error Boundaries & Graceful Fallback UI (3-4 hours)

**Problem:** JavaScript errors crash entire app; users lose work, no recovery path.

**Implementation:**

1. **Implement Svelte error boundaries** [1.5-2 hours]
   - Wrap major components with error boundaries
   - Catch errors at component, route, and app level
   - Display fallback UI instead of white screen:
     ```
     ⚠️ Something went wrong

     An error occurred while loading this component.

     What you can do:
     - Refresh the page
     - Report this issue
     - Return to home

     [Refresh] [Report Issue] [Go Home]
     ```
   - Log errors to console and backend (if telemetry enabled)

2. **Add error reporting** [1-1.5 hours]
   - "Report Issue" opens pre-filled GitHub issue template
   - Include error message, stack trace, user agent
   - Sanitise sensitive data before reporting
   - Optional: Attach reproduction steps

3. **Create error recovery actions** [0.5-1 hour]
   - Retry failed operations automatically (network errors)
   - Offer manual retry button
   - Restore component state after recovery
   - Clear error state on navigation

**Files:**
- `src/webui/components/ErrorBoundary.svelte` (new)
- `src/webui/components/ErrorFallback.svelte` (new)
- `src/webui/lib/error-reporting.ts` (new)

**⚠️ MANUAL TEST:** Trigger errors (network failure, invalid data), verify graceful fallback

**Success Criteria:**
- No white screen crashes
- Users can recover from errors without losing work
- Error messages actionable
- Critical paths have retry mechanisms

## Known Risks

- **Feature creep:** Scope may expand beyond 10 features (mitigate: strict prioritisation)
- **Performance:** Complex filters may slow queries (mitigate: database optimisation, caching)
- **Keyboard shortcut conflicts:** Browser shortcuts may conflict (mitigate: customisable shortcuts)
- **Help content maintenance:** Embedded docs may drift from actual docs (mitigate: automated sync)
