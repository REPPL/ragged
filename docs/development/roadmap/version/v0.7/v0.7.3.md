# Ragged v0.7.3 Roadmap - WebUI Collaboration Features (Conditional)

**Status:** Conditional (implement only if multi-user demand exists)

**Total Hours:** 25-35 hours (AI implementation)

**Focus:** Multi-user collaboration capabilities for team knowledge bases

**Breaking Changes:** None

**Dependencies:** Requires v0.7.2 completion and v0.6.7 authentication backend

**Purpose:** Transform ragged from "single-user tool" to "collaborative team platform"

---

## Overview

Version 0.7.3 adds multi-user collaboration features to the WebUI, enabling teams to share knowledge bases, collaborate on document annotations, and manage users. This version builds on the authentication infrastructure delivered in v0.6.7 (FastAPI with RBAC) and extends it with team-facing UI components.

**Rationale for Conditional Status:** Ragged is currently optimised for single-user scenarios. Multi-user features add significant complexity and may not be needed by most users. Implementation depends on validated demand from teams, enterprises, or community feedback.

### Decision Criteria

**Implement v0.7.3 if:**
- ✓ User requests for collaboration features (>15 independent GitHub issues/requests)
- ✓ Enterprise adoption feedback requires multi-user support
- ✓ Team use cases identified in user research (e.g., research teams, corporate knowledge management)
- ✓ Authentication backend (v0.6.7) is being actively used

**Skip v0.7.3 if:**
- ✗ Single-user scenarios dominate (<5 collaboration requests)
- ✗ Resource constraints (focus on other priorities)
- ✗ Authentication backend unused or problematic

**Decision Point:** After v0.7.2 release and 2-3 weeks of user feedback analysis

---

## Problem Statement

**Current Single-User Limitations:**
- Authentication exists (v0.6.7) but no team-facing UI
- No user registration or profile management UI
- Documents are per-user; cannot share with teams
- No collaborative annotations (comments, highlights, tags across users)
- No activity feed showing team actions
- No user management dashboard for admins
- Permissions exist in backend but not exposed in UI

### Target Outcomes

**After v0.7.3 Implementation:**
- ✅ User authentication UI (login, registration, password reset)
- ✅ Shared document collections (team knowledge bases)
- ✅ Collaborative annotations (comments, highlights, shared tags)
- ✅ Activity feed and audit log UI
- ✅ User management dashboard (admin interface)

## COLLAB-001: User Authentication UI (5-7 hours)

**Problem:** Authentication backend exists (v0.6.7) but no login/registration UI; users must use API directly.

**Implementation:**

1. **Design authentication pages** [1.5-2 hours]
   - Login page: Email/password, "Remember me", "Forgot password?"
   - Registration page: Email, password, confirm password, name
   - Password reset flow: Email verification, reset link
   - Profile page: Edit name, email, password, avatar
   - Modern, accessible design (WCAG 2.1 AA)

2. **Implement authentication forms** [2-3 hours]
   - Svelte components for auth pages
   - Form validation (client-side + server-side)
   - Password strength indicator
   - Email verification flow
   - JWT token storage (httpOnly cookies preferred)
   - Auto-redirect after login

3. **Add social authentication (optional)** [1-1.5 hours]
   - OAuth integration (Google, GitHub)
   - "Sign in with Google/GitHub" buttons
   - Link social accounts to existing accounts

4. **Create session management UI** [0.5-1 hour]
   - "Active sessions" view (logout from other devices)
   - Session timeout warnings
   - "Remember this device" for trusted devices

**Files:**
- `src/webui/pages/Login.svelte` (new)
- `src/webui/pages/Register.svelte` (new)
- `src/webui/pages/Profile.svelte` (new)
- `src/webui/components/auth/PasswordReset.svelte` (new)
- `src/webui/stores/auth.ts` (new - auth state management)

**⚠️ MANUAL TEST:** Register user, login, reset password, verify sessions

**Success Criteria:**
- Registration and login work securely
- Password reset flow completes successfully
- Forms are accessible (keyboard navigation, screen readers)
- Sessions persist correctly

## COLLAB-002: Shared Document Collections (6-8 hours)

**Problem:** Collections (v0.7.1) are per-user; no way to share knowledge bases with team members.

**Implementation:**

1. **Design shared collections UI** [1.5-2 hours]
   - Collection permissions: Private, Team, Public
   - Sharing dialog: Add team members by email
   - Permission levels: Viewer, Editor, Admin
   - Collection ownership transfer

2. **Implement backend sharing logic** [2-3 hours]
   - Extend collections data model (v0.7.1):
     - Add `owner_id`, `permissions` fields
     - Many-to-many relationship: collections ↔ users
   - API endpoints:
     - `POST /collections/{id}/share` - Share with users
     - `GET /collections/{id}/members` - List members
     - `DELETE /collections/{id}/members/{user_id}` - Remove member
   - Enforce permissions on all collection operations

3. **Create team collection browser** [1.5-2 hours]
   - Collections sidebar (v0.7.1) shows:
     - "My Collections"
     - "Shared with Me"
     - "Team Collections"
   - Indicators for shared collections (avatars of members)
   - Filter collections by owner/shared status

4. **Add real-time collaboration** [1-1.5 hours]
   - WebSocket notifications for collection updates
   - Show when team members viewing/editing
   - Presence indicators ("Alice is viewing Collection X")
   - Optimistic UI updates

**Files:**
- `src/webui/components/CollectionSharing.svelte` (new)
- `src/web/routes/collections.py` (modify - add sharing endpoints)
- `src/database/collections.py` (modify - add permissions)
- `src/webui/stores/presence.ts` (new - real-time presence)

**⚠️ MANUAL TEST:** Share collection, verify permissions enforced, test real-time updates

**Success Criteria:**
- Sharing works across users
- Permissions correctly enforced (viewers can't edit)
- Real-time updates appear <1 second
- No permission escalation vulnerabilities

## COLLAB-003: Collaborative Annotations (6-8 hours)

**Problem:** Users cannot comment on documents, highlight passages, or collaborate on analysis.

**Implementation:**

1. **Design annotation UI** [1.5-2 hours]
   - Document viewer with annotation tools:
     - Highlight text (selectable passages)
     - Add comments (thread-based discussions)
     - Tags (shared across team)
   - Annotation sidebar showing all annotations
   - Filter by user, type, date

2. **Implement annotation data model** [2-3 hours]
   - Backend schema: `{id, document_id, user_id, type, content, start_pos, end_pos, created_at}`
   - Types: highlight, comment, tag
   - Thread support for comments (replies)
   - API endpoints:
     - `POST /documents/{id}/annotations` - Create annotation
     - `GET /documents/{id}/annotations` - List annotations
     - `PUT /annotations/{id}` - Update annotation
     - `DELETE /annotations/{id}` - Delete annotation (owner only)

3. **Create collaborative annotation UI** [1.5-2 hours]
   - Highlight overlays on document text
   - Comment threads with replies
   - "Resolve" comments (mark as addressed)
   - Mention users in comments (@alice)
   - Notifications for mentions

4. **Add annotation export** [0.5-1 hour]
   - Export annotations as JSON/CSV
   - Include full context (surrounding text)
   - Useful for research documentation

**Files:**
- `src/webui/components/annotations/AnnotationTools.svelte` (new)
- `src/webui/components/annotations/CommentThread.svelte` (new)
- `src/web/routes/annotations.py` (new - annotation API)
- `src/database/annotations.py` (new - annotation data model)

**⚠️ MANUAL TEST:** Create annotations, verify visible to team, test comment threads

**Success Criteria:**
- Annotations visible to all team members
- Comment threads work correctly
- Mentions trigger notifications
- Export includes full annotation context

## COLLAB-004: Activity Feed & Audit Log UI (4-6 hours)

**Problem:** No visibility into team actions; cannot track who added/modified/deleted documents.

**Implementation:**

1. **Design activity feed UI** [1-1.5 hours]
   - Feed showing recent team actions:
     - "Alice added 5 documents to Collection X"
     - "Bob commented on Document Y"
     - "Charlie modified Collection Z permissions"
   - Group similar actions (collapse repeated actions)
   - Filter by user, action type, date range
   - Real-time updates (new actions appear live)

2. **Implement activity tracking backend** [1.5-2 hours]
   - Log all significant actions to database
   - Schema: `{id, user_id, action_type, target_id, details, timestamp}`
   - Action types: document_added, document_deleted, collection_shared, annotation_created, etc.
   - API endpoint: `GET /activity?range=7d&user_id=...`
   - Pagination for long histories

3. **Create audit log for admins** [1-1.5 hours]
   - Admin-only view showing security-relevant events:
     - Login attempts (successful/failed)
     - Permission changes
     - User account modifications
     - Bulk deletions
   - Export audit log for compliance
   - Retention policy (configurable, default 90 days)

4. **Add activity notifications** [0.5-1 hour]
   - Notify users of relevant activities:
     - Someone commented on your document
     - Collection you own was modified
     - You were mentioned in a comment
   - Notification preferences (email, in-app, none)

**Files:**
- `src/webui/components/ActivityFeed.svelte` (new)
- `src/webui/components/AuditLog.svelte` (new)
- `src/web/routes/activity.py` (new - activity API)
- `src/database/activity_log.py` (new - activity tracking)

**⚠️ MANUAL TEST:** Perform actions, verify appear in feed, test filters

**Success Criteria:**
- All significant actions logged
- Feed updates in real-time (<1s delay)
- Audit log provides compliance trail
- Notifications delivered reliably

## COLLAB-005: User Management Dashboard (Admin Interface) (4-6 hours)

**Problem:** No admin UI for managing users, roles, or permissions; must use backend directly.

**Implementation:**

1. **Design admin dashboard** [1-1.5 hours]
   - User management table:
     - List all users (name, email, role, status)
     - Search and filter users
     - Bulk actions (activate, deactivate, change role)
   - User detail view: Edit profile, reset password, view activity
   - Role management: Create/modify roles, assign permissions

2. **Implement user management backend** [1.5-2 hours]
   - Admin-only API endpoints:
     - `GET /admin/users` - List all users
     - `PUT /admin/users/{id}` - Update user (role, status)
     - `DELETE /admin/users/{id}` - Deactivate user
     - `POST /admin/users/{id}/reset-password` - Force password reset
   - Enforce admin role check (RBAC from v0.6.7)
   - Audit all admin actions

3. **Create role and permissions UI** [1-1.5 hours]
   - Role editor: Define custom roles
   - Permission matrix: Assign permissions to roles
   - Pre-defined roles: Admin, Editor, Viewer, Guest
   - Apply role changes to users

4. **Add team analytics** [0.5-1 hour]
   - Team usage statistics:
     - Active users (last 7/30 days)
     - Document count, query count
     - Storage usage per user
     - Most active users/collections
   - Charts and trends

**Files:**
- `src/webui/pages/admin/UserManagement.svelte` (new)
- `src/webui/pages/admin/RoleManagement.svelte` (new)
- `src/webui/pages/admin/TeamAnalytics.svelte` (new)
- `src/web/routes/admin.py` (new - admin API endpoints)

**⚠️ MANUAL TEST:** Create users, assign roles, verify permissions enforced

**Success Criteria:**
- Admins can manage all users
- Role changes apply immediately
- Permission matrix correctly enforces access
- Team analytics accurate

## Known Risks

- **Concurrency conflicts:** Multiple users editing same document simultaneously (mitigate: operational transformation or CRDTs)
- **Permission complexity:** Role-based access control can become complex (mitigate: clear permission model, testing)
- **Real-time performance:** WebSocket connections scale poorly (mitigate: horizontal scaling, connection pooling)
- **Data privacy:** Shared collections may expose sensitive data (mitigate: clear privacy controls, encryption)
