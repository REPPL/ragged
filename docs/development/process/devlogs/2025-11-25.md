## Decisions Made

### Decision: v0.7 Series Focus Change

**Context**: Original v0.7 planned for "Installation Excellence" but v0.6 had already delivered Svelte WebUI foundation (100-140h work). Jumping directly to installation would abandon incomplete UI work.

**Chosen Approach**: Transform v0.7 into "User Interface Enhancement & Refinement" series, moving installation work to v0.8.

**Alternatives Considered**:
1. Keep v0.7 as installation, accept UI gap until v0.9
2. Merge installation features into v0.7 alongside UI features (scope creep risk)
3. Skip v0.7, go directly to v0.8 with combined UI+installation

**Rationale**:
- Natural progression: v0.6 (UI foundation) → v0.7 (UI completion) → v0.8 (installation) → v0.9 (agents)
- Prevents abandoning 100-140h of WebUI work from v0.6
- Maintains focused scope per series (UI vs Installation)
- Aligns with user feedback priorities (complete working UI before perfecting installation)

**ADR Created**: No (architectural roadmap decision, documented in series overviews)

### Decision: Security Hardening in Both Series

**Context**: User explicitly requested dedicated security hardening versions.

**Chosen Approach**: Add v0.7.4 (WebUI Security) and v0.8.5 (Installation Security).

**Alternatives Considered**:
1. Security as part of other versions (distributed approach)
2. Single security version covering both UI and installation
3. Security-only series (v0.X dedicated to security)

**Rationale**:
- Dedicated versions ensure security is not overlooked
- Separate concerns: WebUI security (XSS, CSRF, auth) vs Installation security (dependency verification, secrets)
- Each version focused enough to complete in 20-35h
- Aligns with best practice (security as explicit milestone)

**ADR Created**: No (planning decision)

### Decision: Embedded ChromaDB as v0.8.4

**Context**: User specifically asked "where is the 'Embedded ChromaDB' going?"

**Chosen Approach**: Place in v0.8.4 as conditional installation option.

**Alternatives Considered**:
1. Keep in v0.7.3 as UI alternative (original placement)
2. Integrated into v0.8.0 as installation mode option
3. Separate series for Docker-free deployment

**Rationale**:
- Embedded ChromaDB is an installation method, not a UI feature
- Natural fit after core installation (v0.8.0-v0.8.2) proves itself
- Conditional status appropriate (not all users need Docker-free mode)
- Follows platform-specific installers (v0.8.3), maintains logical flow

**ADR Created**: No (roadmap organisation decision)
